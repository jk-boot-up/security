Secure design

OWASP Top 10 (2025) A06 Insecure Design: finding threats before code is written, deciding what to do about each, and turning those decisions into checks that keep holding as the design changes.

The projects

# Project What it shows Maps to
1 threat-modeling A bank as a data-flow model in code, STRIDE threats found per element and boundary, rated and decided, with mitigations kept as tests that fail when the model drifts A06, SSDF PW.1
2 security-requirements-with-asvs Choosing an ASVS level, requirements kept as data, automated checks against a running store, coverage by chapter and a release gate ASVS 5.0, A06, SSDF PW.1
3 attack-trees-and-abuse-cases Draw how the attacker wins, price each step, then cut the cheapest path and look again A06
4 threat-modeling-with-pytm Describe the bank once, let pytm check its 113 threats against every element and flow, and watch each honest answer remove findings A06, SSDF PW.1
5 attack-trees-and-abuse-cases-with-threat-dragon Put the bank's abuse cases in a model file that OWASP Threat Dragon opens, check it with the editor's own validator, and let the plan turn threats from Open to Mitigated A06

A project with -with- in its name is the same lesson with a framework or a local tool, and is its own self-contained project.

How the module is judged

  • Break it, then fix it, or build the control and prove each refusal with a test.
  • Every claim is a number that a test checks against a golden output file.
  • A threat model for every project, with a diagram, in docs/threat-model.md.
