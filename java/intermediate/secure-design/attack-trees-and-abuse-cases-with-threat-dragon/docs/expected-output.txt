TWO. Checked by Threat Dragon's own validator.
  the image owasp/threat-dragon:v2.6.2 carries the schema in its editor bundle and the Ajv that checks it; both are used as they are
  the bank's model: valid
  no title: refused, [.summary should have required property 'title']
  short type: refused, [.detail.diagrams[0].diagramType should NOT be shorter than 3 characters]
  no id: refused, [.detail.diagrams[0].cells[2] should have required property 'id']
  tiny: refused, [.detail.diagrams[0].cells[2].size.width should be >= 10]
  the editor refuses a file that fails these checks when it is opened, so a file generated by a program is checked the same way before anyone opens it

FOUR. Checks the schema cannot make.
  rules over the file: complete threats, known status and severity, a STRIDE type, a mitigated threat names its defence, the open flag of a cell matches its threats, flows end at cells that exist, threatTop is the highest number, every abuse case has a threat
  the model before the plan: 0 problems; after the plan: 0
  no mitigation: [mitigated-names-its-defence (Web app / AC4)]
  stale flag: [open-flag-matches-threats (Web app)]
  lost end: [flow-ends-exist (Sign in with password and one-time code target)]
  bad count: [threat-top-is-highest-number (threatTop 3 but highest 8)]
  a file that a program writes can be wrong in ways a schema does not know, and so can a file that people edit in the editor
FIVE. The editor, and the bill.
  the editor's server started from the image, with generated keys, on a loopback port: health 200, the page 200 titled OWASP Threat Dragon
  providers it offers: bitbucketEnabled:false,githubEnabled:false,gitlabEnabled:false,googleEnabled:false,localEnabled:true
  its model API without signing in: 401; a model is opened in the browser from a file, in a local session, and saved back to a file or a repository
  the threats are flat and typed by STRIDE: cost, chance and the AND and OR of the tree live in the description and the score text, so the tree is kept where it can be calculated
  the file is JSON with positions and identifiers, which a program can write and a reviewer can diff; the picture is drawn by the editor from it
  Threat Dragon stores no tests: whether a Mitigated threat is true is what the abuse cases in the code say
