ONE. A certificate authority that runs.
  THE ROOT (made by step ca init):
    subject      Shop Internal CA Root CA
    self-signed  true
    valid        10 years
    key file     secrets/root_ca_key, encrypted: true
  THE ISSUING AUTHORITY:
    subject      Shop Internal CA Intermediate CA
    signed by    the root: true
    path length  0: it may not create authorities
    valid        10 years
  THE CA'S POLICY (in ca.json):
    allowed names  localhost, *.shop.localhost
  THE REQUEST: GET /health over https
  THE RESPONSES:
    a client that trusts the root: ok
    a client without the root: refused (PKIX path building failed)
TWO. A certificate for a service, with a token.
  THE TOKEN (step ca token www.shop.localhost):
    parts        3: header.payload.signature
    header       alg ES256, typ JWT
    sub          www.shop.localhost
    sans         [www.shop.localhost]
    iss          tokens (the provisioner that signed it)
    aud          <ca address>/1.0/sign
    exp - nbf    300 seconds
    sha          the SHA-256 of the root: true
    jti          <random id, 64 characters>
  THE CERTIFICATE (step ca certificate ... --token):
    issued, [www.shop.localhost], 24 hours, key EC
    serial <random>, issued by Shop Internal CA Intermediate CA
    a client that trusts the root: accepted
  THE TOKENS THE CA REFUSES:
    the same token a second time
      -> refused (not authorized)
    a token for api.shop.localhost, used for www
      -> refused (the token was issued for another name)
    a valid token, asking for 2000 hours
      -> refused (longer than the longest lifetime the CA allows)
    a valid token for pay.example
      -> refused (that name is outside what the CA's policy allows)
THREE. A certificate for a service, with ACME.
  THE REQUEST (step ca certificate --provisioner acme):
    www.shop.localhost; the CA calls it back on port 80
  THE CERTIFICATE:
    issued, [www.shop.localhost], 24 hours, key EC
    serial <random>, issued by Shop Internal CA Intermediate CA
    a client that trusts the root: accepted
  ACME FOR A NAME OUTSIDE THE POLICY (evil.example):
    -> refused (the ACME server will not issue for that name)
FOUR. Renewing before it ends.
  BEFORE THE RENEWAL (www.shop.localhost):
    serial <random>, 24 hours, key EC
  AFTER step ca renew (the certificate and its key):
    renewed, 24 hours
    a new serial: true; the same key: true; ends later: true
  AFTER step ca rekey:
    renewed; a different key: true
  A SERVICE THAT LOST ITS KEY (renews with another key):
    -> refused (the key does not match: the TLS call fails)
    <- ONLY THE HOLDER OF THE KEY RENEWS
FIVE. Revocation, and the bill.
  THE REVOCATION (step ca revoke, the acme certificate):
    revoked: true
    a renewal afterwards
      -> refused (not authorized)
  THE REVOCATION LIST (GET /1.0/crl):
    signed by    Shop Internal CA Intermediate CA: true
    entries      1; the acme serial: true
    current for  5 minutes (next update - this update)
  THE CHECKS:
    acme, the client checks the list
      -> refused (REVOKED)
    acme, a client that never checks
      -> accepted  <- A REVOKED CERTIFICATE STILL WORKS
    acme, a client that wants to check but has no list
      -> refused (UNDETERMINED_REVOCATION_STATUS)
      <- NO LIST, SO NO: IT FAILS CLOSED
    www.shop.localhost, the same list
      -> accepted
  THE KEYS THE CA HOLDS (the bill):
    issuing  secrets/intermediate_ca_key, online, encrypted: true
    root     secrets/root_ca_key, same disk, encrypted: true
