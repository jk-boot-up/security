== 1. An app that trusts the device ==
genuine server                                         -> ACCEPTED
interception by the device's extra root                -> ACCEPTED

== 2. An app that pins the server's key ==
genuine server                                         -> ACCEPTED
interception by the device's extra root                -> REFUSED_BY_PIN
interception on a clean device                         -> REFUSED_BY_VALIDATION

== 3. The server renews with a new key ==
app pinned to the old leaf key                         -> REFUSED_BY_PIN
fleet of 10000 installs, 85% update within a week -> locked out on day 0: 10000, after a week: 1500

== 4. Pins chosen so that rotation does not break the app ==
pin the issuing CA's key                               -> ACCEPTED
interception, same app                                 -> REFUSED_BY_PIN
pin leaf + backup, server switches to the backup key   -> ACCEPTED
report-only mode, after a key change                   -> ACCEPTED_REPORT_ONLY
reports collected -> 1

== 5. Why browsers stopped letting servers set pins ==
a meddler answers one request with a pin header for the meddler's keys, max-age one year
the genuine server, 30 days later -> blocked for every returning visitor
the genuine server, 400 days later -> accepted again
a site pins its own key and then loses it -> blocked for up to a year
