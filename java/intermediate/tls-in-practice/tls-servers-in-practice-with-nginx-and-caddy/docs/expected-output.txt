THREE. HSTS, and the add_header trap.
BEFORE THE FIX (no add_header line):
  GET / over https  Strict-Transport-Security: (none)
THE LINE ADDED TO THE SERVER BLOCK:
  add_header Strict-Transport-Security
    "max-age=31536000; includeSubDomains" always;
AFTER THE FIX (Strict-Transport-Security in the response):
  GET / over https  max-age=31536000; includeSubDomains
  GET / over http   (none)
THE max-age, WORKED OUT:
  31536000 s / 86400 s a day = 365 days
  includeSubDomains: yes, so every name under www.shop.localhost too
THE TRAP (/account has an add_header of its own):
  location /account {
      add_header X-Frame-Options DENY always;
  }
THE RULE, BY HAND (a location's own lines replace the server's):
  server    [Strict-Transport-Security]
  location  [X-Frame-Options]
  applied   [X-Frame-Options]
THE RESPONSE FROM GET /account:
  X-Frame-Options: DENY
  Strict-Transport-Security: (none)  <- THE SERVER'S LINE IS LOST
AFTER THE FIX (the line repeated in the location):
  X-Frame-Options: DENY
  Strict-Transport-Security: max-age=31536000; includeSubDomains
