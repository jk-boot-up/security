ONE. nginx with a certificate from the local authority.
  a client that trusts the lab's root asks for www.shop.localhost: 200 over TLSv1.3
  a client that trusts only its own default roots: refused (the certificate is not signed by anything this client trusts)
  the same client, asking for pay.shop.localhost, which the certificate does not name: refused (the certificate is not for that name)
  plain http on its own port: 301, sent on to https: true
  by default the Server header gives the exact version of nginx: true
  with server_tokens off it says only: nginx
TWO. Which protocol versions it speaks.
  the default accepts a client that offers only TLS 1.2: 200 over TLSv1.2; and one that offers 1.3: 200 over TLSv1.3
  with ssl_protocols TLSv1.3, the client that offers only 1.2: refused (no protocol version in common); the one that offers 1.3: 200 over TLSv1.3
  the price of the stricter setting is every client that cannot speak 1.3; the setting is one line, and a change needs a reload
THREE. HSTS, and the add_header trap.
  by default the response has Strict-Transport-Security: false
  with add_header in the server block: max-age=31536000; includeSubDomains; over plain http, where a browser would ignore it, it is sent: false
  /account has its own add_header (X-Frame-Options): the page has X-Frame-Options: DENY and Strict-Transport-Security: false  <- A LOCATION'S add_header REPLACES THE SERVER'S
  repeating it in the location: Strict-Transport-Security: true
  a browser that has seen the header refuses plain http to this name for a year; max-age is a promise that is hard to take back
FOUR. Caddy makes its own certificates.
  the Caddyfile names only the site; Caddy made a root, an intermediate and a certificate by itself: 200 over TLSv1.3, chain of 2, issued by Caddy Local Authority - ECC Intermediate
  the certificate lasts 12 hours, and Caddy renews it on its own
  a client that trusts nginx's root but not Caddy's: refused (the certificate is not signed by anything this client trusts)
  plain http: 308, sent on to https: true
  the Server header says only: Caddy; Strict-Transport-Security by default: false
  a client that offers only TLS 1.2 is accepted by default: 200 over TLSv1.2
  with a header line in the Caddyfile: max-age=31536000; includeSubDomains
FIVE. The bill.
  ssl_stapling on, and the client asks for a stapled OCSP answer: 0 received; nginx says it found no responder to ask: true  <- STAPLING NEEDS A RESPONDER IN THE CERTIFICATE
  Caddy's local certificates carry no responder either, so nothing is stapled: 0 received
  a new certificate is written over the old file: on disk it is new: true, nginx still serves the old one: true  <- NGINX READS THE FILE ONLY WHEN IT STARTS OR RELOADS
  after nginx -s reload it serves the new one: true
  nginx needs a renewal job that ends with a reload; Caddy renews and swaps by itself, and needs its data folder kept, because that folder holds the keys of its local authority
  every client needs the root of whichever authority signed: the lab's for nginx, Caddy's for Caddy; the browser's own list contains neither
