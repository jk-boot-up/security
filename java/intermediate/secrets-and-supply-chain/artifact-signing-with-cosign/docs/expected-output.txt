ONE. A deployment that runs whatever a tag points at.
  BEFORE (the release team pushes shop/app:2.4.0):
    tag 2.4.0   -> digest A, the release
    a digest    sha256 of the image's manifest: a checksum
    pull 2.4.0  gets the release: true
  AFTER (someone with push rights reuses the tag):
    tag 2.4.0   -> digest B, another image
    the same?   digest A = digest B: false
    pull 2.4.0  gets the release: false  <- A TAG IS A NAME
    pull by A   gets the release: true
  WHY A DIGEST ALONE IS NOT ENOUGH:
    it must come from somewhere that cannot be changed
TWO. A signed release, checked before it runs.
  BEFORE SIGNING (what cosign signs for digest A):
    type     https://sigstore.dev/cosign/sign/v1
    digest   docker-manifest-digest = digest A
    for      docker-reference = .../shop/app@<digest A>
    claims   (none)
  AFTER SIGNING (with the release key):
    signed     true
    stored as  one more tag: sha256-<digest A>
    the tag    not signed: the payload names the digest
  THE GATE (pins release.pub, resolves the tag):
    tag -> digest A         accepted  signed by the release key
    moved -> digest B       refused   no signature for this digest
    digest B, attacker key  refused   not signed by this key
    back -> digest A        accepted  signed by the release key
THREE. Signed claims, and keys that rotate.
  BEFORE (digest A signed again, with claims):
    claims   channel=stable version=2.4.0
    signed   inside the payload: they cannot be edited
    a beta   digest C, claims channel=beta
  AFTER (gates that require a claim):
    stable gate, digest A   accepted  signed by the release key
    beta gate, digest A     refused   claims do not match the gate
    stable gate, digest C   refused   claims do not match the gate
  THE ROTATION (from the release key to next):
    trusts both, digest A   accepted  signed by the release key
    trusts next, digest A   accepted  signed by the next key
    trusts next, digest C   refused   not signed by this key
  BEFORE: A THIEF WITH THE RETIRED old KEY, TODAY:
    image    digest D, signed with old
    time     none: a signature carries no date
  AFTER: THE GATES:
    still trusts old        accepted  signed by the old key
    <- NO LOG, SO NO DAY TO REVOKE FROM
    dropped old             refused   not signed by this key
FOUR. Signed statements about how the image was built.
  BEFORE (the provenance the CI system signs):
    image    digest A
    builder  https://ci.shop.example
    source   git+https://git.shop.example/shop@abc123
    signed   with the release key, type slsaprovenance: true
  AFTER (the signature, then the gate's rule: builder = CI):
    image          signature  builder                 rule
    digest A       accepted   https://ci.shop.example accepted
    digest E       accepted   https://laptop.local    refused
    <- A SIGNATURE SAYS WHO; THE RULE CHECKS WHAT
  FORGED AND BORROWED ATTESTATIONS:
    signed by attacker     refused   not signed by this key
    for digest F instead   refused   no signature for this digest
  LEFT OUT IN THIS LOCAL LAB:
    the public transparency log, where a monitor reads
    every signature
FIVE. The bill.
  THE GATE GUARDS ONE PATH:
    unsigned image    refused   no signature for this digest
    a direct pull     gets digest F anyway: true
  THE SIGNING KEY IS THE CROWN JEWEL:
    wrong passphrase  cannot sign
  ROTATION IS A PROJECT:
    every gate trusts the new key before the old one goes,
    and nothing marks the day an old signature was made
  KEYLESS SIGNING:
    short-lived certificates tied to an identity, logged
    in public: needs the Fulcio and Rekor services
  COSIGN 3:
    offline signing moves behind a signing config,
    so the flags used here may change
