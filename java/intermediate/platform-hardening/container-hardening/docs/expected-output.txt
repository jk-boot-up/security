ONE. What 'docker run' with no options gives an attacker.
  THE SETTINGS (docker run shop-app:latest):
    user            root
    privileged      no
    capabilities    14, Docker's default set
    root files      writable
    new privileges  allowed
    seccomp         RuntimeDefault
    host access     none
    limits          none
    secrets         in the environment
  THE ATTACKS, BY WHAT THEY REACH:
    inside the container:
      read-secrets        POSSIBLE secrets in the environment
      tamper-with-app     POSSIBLE root file system writable
      drop-and-run        POSSIBLE root file system writable
      become-root         POSSIBLE it already runs as root
    the kernel:
      dangerous-syscalls  blocked  default seccomp blocks them
      sniff-network       POSSIBLE root with NET_RAW
      mount-host          blocked  no SYS_ADMIN
    the host:
      docker-socket       blocked  no Docker socket
      host-files          blocked  no host directories mounted
      host-network        blocked  its own network namespace
      see-host-processes  blocked  its own process namespace
    the node's resources:
      exhaust-memory      POSSIBLE no memory limit
      fork-bomb           POSSIBLE no process limit
  HOW THE COUNT IS MADE:
    container 4 + kernel 1 + host 0 + resources 2 = 7 of 13
  HOW THE LEVEL IS MADE:
    baseline    not privileged              pass
    baseline    no host network             pass
    baseline    no host PID namespace       pass
    baseline    no host path volumes        pass
    baseline    seccomp not unconfined      pass
    baseline    only default capabilities   pass
    restricted  not root                    FAIL
    restricted  no privilege escalation     FAIL
    restricted  drops ALL capabilities      FAIL
    level       BASELINE (baseline passes, restricted fails)
