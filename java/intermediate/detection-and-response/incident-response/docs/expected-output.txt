== 1. The attack ==
01:00 an attacker gets into web01 through a flaw in the application
01:05 reads the database password from the configuration
01:20 starts copying the customer table from db01, 1000 rows a minute, 50000 customers in all
01:40 adds three ways back in: a cron job and an SSH key on web01, and a hidden admin account called svc-backup

== 2. What was prepared ==
nothing     0 of 6 in place; missing: no written runbook and contact list, no alert on unusual database reads, logs not kept centrally for at least 7 days, no way to snapshot memory and disk, no known-good image to rebuild from, backups never tested
alert only  1 of 6 in place; missing: no written runbook and contact list, logs not kept centrally for at least 7 days, no way to snapshot memory and disk, no known-good image to rebuild from, backups never tested
full        6 of 6 in place

== 3. Response A: nothing prepared, and a panicked fix ==
day 3 01:00    detect                     a customer reports that their data is being sold
day 3 01:03    reboot web01               memory evidence lost; cron job and SSH key survive the reboot
day 3 01:13    rotate database password   the stolen password no longer works
day 3 01:23    reconnect web01            back in service with 4 way(s) back in still open
day 3 03:23    monitor for 2 hours        THE ATTACKER IS BACK, using the cron job on web01

== 4. Response B: an alert, but no plan ==
day 0 01:30    detect                     alert: unusual database reads
day 0 01:35    isolate web01              network rule blocks it, memory kept; the route to db01 is cut
day 0 03:35    rebuild web01              by hand, with no image: slow, and nobody is sure it is clean
day 0 03:45    reconnect web01            back in service with 3 way(s) back in still open
day 0 05:45    monitor for 2 hours        THE ATTACKER IS BACK, using the hidden admin account svc-backup

== 5. Response C: the playbook ==
day 0 01:30    detect                     alert: unusual database reads
day 0 01:35    isolate web01              network rule blocks it, memory kept; the route to db01 is cut
day 0 01:37    kill database sessions     the attacker's session on db01 is ended
day 0 01:52    capture evidence           memory and disk of web01 snapshotted, logs collected with hashes
day 0 02:12    scope from logs            start 01:00, web01 and db01 involved, svc-backup created at 01:40
day 0 02:22    rotate database password   the stolen password no longer works
day 0 02:25    disable svc-backup         the hidden admin account is removed
day 0 02:55    patch the flaw             the way in is closed
day 0 03:35    rebuild web01              from the known-good image: cron job and SSH key are gone
day 0 03:45    reconnect web01            back in service
day 0 05:45    monitor for 2 hours        quiet
