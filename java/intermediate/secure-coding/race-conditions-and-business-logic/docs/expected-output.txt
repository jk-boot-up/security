ONE. Check, then act: two requests in the gap.
  THE REQUESTS (ana's account ANA-1 holds 100):
    A            withdraw 80, from her phone
    B            withdraw 80, from her laptop, at the same moment
    each         reads the balance, checks it covers 80, writes
  THE STEPS, IN THE ORDER ABABAB:
    A reads the balance: 100
    B reads the balance: 100
    A checks that 100 covers 80: yes
    B checks that 100 covers 80: yes
    A writes 20 and pays out 80
    B writes 20 and pays out 80
  THE RESULT:
    A            paid out 80
    B            paid out 80
    paid out     80 + 80 = 160 from a balance of 100  <- OVERDRAWN
    balance      20: B wrote 100 - 80 over A's 20
  ONE AFTER THE OTHER, IN THE ORDER AAABBB:
    A            paid out 80
    B            refused: B checks that 20 covers 80: no
  EVERY ORDER OF A'S 3 STEPS AND B'S 3 STEPS (20):
    AAABBB 80   AABABB 160  AABBAB 160  AABBBA 160  ABAABB 160
    ABABAB 160  ABABBA 160  ABBAAB 160  ABBABA 160  ABBBAA 160
    BAAABB 160  BAABAB 160  BAABBA 160  BABAAB 160  BABABA 160
    BABBAA 160  BBAAAB 160  BBAABA 160  BBABAA 160  BBBAAA 80
    pays 160     18 of 20 orders
    pays 80      2: only one request after the other
  A SINGLE-USE COUPON SUMMER20 (20 off), IN THE ORDER ABABAB:
    A checks that SUMMER20 is unused: yes
    B checks that SUMMER20 is unused: yes
    A takes 20 off the order
    B takes 20 off the order
    A marks SUMMER20 used
    B marks SUMMER20 used
  THE RESULT:
    discount     20 + 20 = 40 instead of 20  <- THE SAME GAP
TWO. Making the check and the write one step.
  WITH A LOCK ON ANA-1, IN THE ORDER ABABABAB:
    A takes the lock ANA-1
    B waits for the lock ANA-1
    A reads the balance: 100
    B waits for the lock ANA-1
    A checks that 100 covers 80: yes
    B waits for the lock ANA-1
    A writes 20, pays out 80 and releases the lock
    B takes the lock ANA-1
    B reads the balance: 20
    B checks that 20 covers 80: no
    B refuses and releases the lock
  THE RESULT:
    A            paid out 80
    B            refused
    paid out     80, balance 100 - 80 = 20
  WITH A COMPARE-AND-SET, NO LOCK, IN THE ORDER ABABAB:
    A reads the balance: 100
    B reads the balance: 100
    A checks that 100 covers 80: yes
    B checks that 100 covers 80: yes
    A sets 100 to 20 and pays out 80
    B tries to set 100 to 20: the balance changed, start again
    B reads the balance: 20
    B checks that 20 covers 80: no, refused
  HOW B'S COMPARE-AND-SET DECIDES:
    B read       100
    now          20, written by A after B read
    100 = 20?    no: nothing is written, B reads again
  THE RESULT:
    A            paid out 80
    B            refused
    paid out     80, balance 20

THREE. Sending the same request twice.
  THE REQUEST (ana pays ben 300 rent):
    transfer     ANA-1 -> BEN-2, 300
    balances     ana 1000, ben 0
    the reply    is lost, so the app sends the same request again
  BEFORE THE FIX (no key):
    send 1       moved 300: ana 700, ben 300
    send 2       moved 300: ana 400, ben 600  <- PAID TWICE
  AFTER THE FIX (the app sends the key rent-october):
    send 1       moved 300: ana 700, ben 300
    send 2       already done: moved 300: ana 700
    amount 900   refused: the key was used for another transfer
    new key      rent-november: moved 300: ana 400
  HOW THE BANK READS A KEY:
    new key      claim it in one step, move, keep the answer
    repeated     return the kept answer, move nothing
    changed      refuse: a key names one request
    two at once  only one claim succeeds, the other waits
