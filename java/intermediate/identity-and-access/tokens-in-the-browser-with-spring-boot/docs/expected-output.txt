TWO. A backend for the frontend keeps the tokens on the server.
  THE SIGN-IN (Spring's oauth2Login on the BFF, client bank-bff):
    Set-Cookie: __Host-bff=<session id>
      Path=/; Secure; HttpOnly; SameSite=Strict
    Set-Cookie: XSRF-TOKEN=<random>; Path=/
  THE COOKIE'S RULES (__Host-bff):
    Secure           sent over HTTPS only
    HttpOnly         scripts on the page cannot read it
    SameSite=Strict  not sent when another site starts it
    __Host- prefix   Secure, Path=/, no Domain: true
  WHERE THE TOKENS ARE:
    the BFF's OAuth2AuthorizedClientService  2 tokens
    the browser                              0 tokens
  THE APP'S OWN REQUEST (only the cookie goes with it):
    GET /api/accounts -> 200 balance 125000 cents
  THE SAME SCRIPT ON THE PAGE READS document.cookie:
    [XSRF-TOKEN] -> 0 tokens; __Host-bff is not readable: true
  WHAT THE SCRIPT CAN STILL DO:
    page open    GET /api/accounts -> 200 balance 125000 cents

  SIX MINUTES LATER (the access token has expired):
    the browser sends the cookie -> 200 balance 125000 cents

THREE. Requests started by another site.

      -> 401 (invalid_dpop_proof)
