ONE. OAuth gives access; OpenID Connect adds who signed in.
  THE REQUEST (the store sends Ana's browser to the bank):
    https://bank.example/authorize
    client_id    store-web
    redirect_uri https://shop.example/callback
    scope        openid email
    state        <random, kept for this browser>
    nonce        <random, kept for this browser>
  THE RESPONSE (the bank's token endpoint, two tokens):
    ID token      typ JWT     aud store-web
    access token  typ at+jwt  aud https://api.bank.example
  THE ID TOKEN'S CLAIMS (who signed in, for whom, when):
    iss        https://bank.example  (who says so)
    sub        ana-0001  (who signed in)
    aud        store-web  (for which app)
    iat        1800000000  (issued, seconds since 1970)
    exp        1800000300  = iat + 300 seconds
    auth_time  1800000000
    nonce      <random>  equals the one kept: true
    acr, amr   urn:example:loa:2, [pwd, otp]
    sid        sid-1  (the bank's session)
    email      ana@mail.example, email_verified true
  THE RESULT:
    Ana is signed in as https://bank.example | ana-0001
  THE ACCESS TOKEN, OFFERED AS PROOF OF SIGN-IN:
    refused: not an ID token (typ at+jwt)
    <- AN ACCESS TOKEN SAYS WHAT IS ALLOWED, NOT WHO
  A SIGN-IN WITHOUT THE openid SCOPE (scope accounts.read):
    refused: no ID token: the reply gives API access, not a sign-in
TWO. Checking the ID token, as OpenID Connect Core requires.
  BEFORE SIGNING (a header and the claims, as JSON):
    header  {"alg":"EdDSA","typ":"JWT","kid":"bank-2026-a"}
    claims  {"iss":"https://bank.example","sub":"ana-0001","...
            (12 claims, 269 bytes)
  HOW THE BANK SIGNS IT (step by step):
    1. header part = base64url(header)
       eyJhbGciOiJFZERTQSIsInR5cCI6IkpXVCIsImtp... (63 chars)
    2. claims part = base64url(claims)
       eyJpc3MiOiJodHRwczovL2JhbmsuZXhhbXBsZSIs... (359 chars)
    3. signing input = header part + "." + claims part
       423 bytes
    4. signature = Ed25519(private key bank-2026-a, input)
       64 bytes = UI6r94hBknp3AuKcenaIT8oDKgqYflbp... (86 chars)
  AFTER SIGNING (the ID token: three parts, joined by dots):
    eyJhbGciOiJF....eyJpc3MiOiJo....UI6r94hBknp3...
    510 characters in all
  HOW THE STORE CHECKS IT (in this order):
    1. alg is EdDSA, the store's choice: true
    2. kid bank-2026-a is in the published keys: true
    3. Ed25519 verify with that public key: true
    4. iss equals https://bank.example exactly: true
    5. aud contains store-web: true
    6. now 1800000000 < exp 1800000300 + 30: true
    7. nonce equals nonce-for-this-browser: true
  THE RESULT:
    accepted
  ONE THING CHANGED AT A TIME (the input, then the result):
    claims signed with a key the bank never published
      -> refused: signature does not match
    iss https://bank.example/ (one extra slash)
      -> refused: issuer is not the configured issuer
    iss https://wallet.example, signed by the bank
      -> refused: issuer is not the configured issuer
    aud budget-app
      -> refused: audience does not include this client
    aud [store-web, budget-app], no azp
      -> refused: several audiences and no azp naming this client
    aud [store-web, budget-app], azp store-web
      -> accepted
  THE NONCE AND THE HEADER (input, then result):
    nonce someone-elses-nonce, from another sign-in
      -> refused: nonce is not the one this browser was given
      <- A TOKEN FROM ANOTHER LOGIN CANNOT BE REPLAYED
    no nonce at all
      -> refused: no nonce
    header {"alg":"none","kid":"bank-2026-a"}, no signature
      -> refused: algorithm is not EdDSA
  THE TIME CHECK (now 1800000000, skew 30 seconds):
    exp 1799999971, 29 s ago: exp + 30 = 1800000001 > now
      -> accepted
    exp 1799999970, 30 s ago: exp + 30 = 1800000000 = now
      -> refused: expired
THREE. Discovery and keys.
  THE CONFIGURATION (the store knows one value):
    issuer https://bank.example
  THE REQUEST (the address is made from the issuer):
    GET https://bank.example/.well-known/openid-configuration
  THE RESPONSE (the metadata, the fields the store uses):
    issuer                 https://bank.example
    authorization_endpoint https://bank.example/authorize
    token_endpoint         https://bank.example/token
    userinfo_endpoint      https://bank.example/userinfo
    jwks_uri               https://bank.example/jwks.json
    end_session_endpoint   https://bank.example/logout
    signing algorithms     [EdDSA]
  THE CHECKS:
    issuer equals the configured issuer: true
    jwks_uri on the issuer's own site: true
  THE KEYS (GET https://bank.example/jwks.json):
    kid bank-2026-a, kty OKP, crv Ed25519, use sig
    x = 0EqyMnQrtKs6E2i9RhXk5tAiSrcaAWuvhSCjMsl3hzc
    x is the public key the bank made from its private seed:
    seed 11 11 11 ... 11 (32 bytes, never published)
    store's key ids: bank-2026-a
  FORGED METADATA AT THE SAME ADDRESS (input, then result):
    issuer https://wallet.example
      -> refused: the metadata names another issuer
      <- ONE PROVIDER CANNOT POSE AS ANOTHER
    jwks_uri https://keys.example/jwks.json
      -> refused: the key set is not on the issuer's own site
  KEY ROTATION (step by step):
    1. the bank adds bank-2026-b and signs new tokens with it
       the store reloads the keys: bank-2026-a, bank-2026-b
       old token: accepted; new token: accepted
    2. the bank retires bank-2026-a; the store reloads the keys:
       bank-2026-b
       old token: refused: unknown key id
       new token: accepted
  OVER REAL HTTP ON THIS MACHINE (port not printed):
    metadata and keys loaded: [loop-1]
    an ID token from that provider: accepted

    Ana's access token
      -> sub ana-0001, email ana@mail.example

FIVE. Signing out, and the bill.
  ANA SIGNS OUT AT THE STORE (RP-initiated logout):
    the store's session ended: true
    her browser is sent to https://bank.example/logout
    ?id_token_hint=<her ID token>
    &post_logout_redirect_uri=https%3A%2F%2Fshop.example%2Fsigned-out
    &state=<random>
  BEFORE THE LOGOUT TOKEN (Ana on two devices):
    store sessions: 2; laptop sid-3, phone sid-5
  THE LOGOUT TOKEN (the bank ends the laptop's session):
    header  typ logout+jwt, alg EdDSA, kid bank-2026-a
    claims  iss https://bank.example, aud store-web
            sub ana-0001, sid sid-3, jti lt-7
            events: http://schemas.openid.net/event/backchannel-logout
            nonce: none
  AFTER THE LOGOUT TOKEN:
    accepted
    store sessions: 1; laptop signed in: false; phone: true
  BROKEN LOGOUT TOKENS (input, then result):
    a logout token with a nonce
      -> refused: a logout token must not have a nonce
    a logout token without the event
      -> refused: no logout event
    an ID token sent as a logout token
      -> refused: not a logout token
  THE BILL:
    many checks and options: use a certified library
    the ID token stays in the store; never take an access token
      as a sign-in
    sign-out must reach the store, the provider and every app
