  THE THUMBPRINT, WORKED OUT (RFC 7638):

  THE ACCESS TOKEN CARRIES IT (claim cnf.jkt):
    M_644r-O_ojiozY7030u6L0vgywDOQhLCmAGa7hHBZY  = the thumbprint
  THE PROOF FOR ONE REQUEST (a small JWT signed by the key):
    typ dpop+jwt, alg EdDSA, jwk <the public key above>
    jti  <16 random bytes>  (used once)
    htm  GET
    htu  https://api.bank.example/accounts
    iat  1790000000
    ath  ZiuW0T4rEXnfYYAjokGts9IE8JYXWTZ5OFisVtoYiWk
         = SHA-256 of the access token, in base64url
  THE APP'S OWN REQUEST (Authorization: DPoP <token>, DPoP: <proof>):
    GET /accounts -> 200 balance 1200.00
  THE ATTACKS (a script took the token from localStorage):
    the token alone, as a plain bearer token
      -> 401 (this token is bound to a key: a DPoP proof is required)
    with a proof from the thief's own key
      -> 401 (the proof's key is not the key the token is bound to)
    the app's own request, copied and sent again
      -> 401 (the proof was already used)
    the app's proof for GET /accounts, used for a transfer
      -> 401 (the proof was made for another request)
    a proof made 120 s ago (the token is still valid)
      -> 401 (the proof is too old)
  THE REFRESH TOKEN, BOUND TO THE SAME KEY:
    stolen, with the thief's key  -> refused
    the app, with its own key     -> new tokens
  a stolen token is useless without the key,
  and the key never leaves the browser
