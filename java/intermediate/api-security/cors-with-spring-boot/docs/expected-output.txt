== 1. No policy: a page may send, but not read ==
bank's own page reads /account           -> reached the bank, readable: balance: 125000 cents
evil.example reads /account              -> reached the bank, answer blocked
evil.example POSTs /transfer (simple)    -> reached the bank, answer blocked
evil.example PUTs /transfer              -> never reached the bank, answer blocked
requests the bank processed              -> [GET /account, POST /transfer]  <- CORS DID NOT STOP THE POST

== 5. The bill ==
public /rates sends                      -> Allow-Origin *
browser accepts * without credentials    -> true
browser accepts * with credentials       -> false
evil.example POSTs /transfer (simple)    -> never reached the bank, answer blocked
the same POST with no Origin header      -> 200 sent 500 to mallory  <- CORS IS A BROWSER RULE, NOT A DEFENCE
requests the bank processed              -> [POST /transfer]
every allowed origin needs a test, and so do the lookalike, the null origin and the preflight
a policy decides who may read an answer; who may act still needs a login and a token
