    401, Access-Control-Allow-Origin: (none)

FOUR. The policy must sit before the login check.
  THE ORDER A REQUEST GOES THROUGH:
    1. Spring Security: http.cors, then the login check
    2. Spring MVC: addCorsMappings, then the controller
  REGISTERED IN SPRING MVC (addCorsMappings):
    preflight for PUT (no login)  401
    GET  /account                 read: balance: 125000 cents
    PUT  /transfer                never reached the bank
  REGISTERED IN SPRING SECURITY (http.cors):
    preflight for PUT (no login)  200
    GET  /account                 read: balance: 125000 cents
    PUT  /transfer                read: sent 500 to mallory
  a preflight never carries a login, so it must pass before one
FIVE. CORS is a browser rule, not a defence.
  THE PUBLIC ANSWER (GET /rates):
    Access-Control-Allow-Origin: *
  THE BROWSER'S CHECK OF *:
    without credentials  -> accepted
    with credentials     -> refused
  A POST /transfer FROM A PAGE ON https://evil.example:
    never reached the bank
  THE SAME POST FROM A SERVER SCRIPT (no Origin header):
    200 sent 500 to mallory  <- NO BROWSER, NO CORS
  THE BANK'S LOG (the requests it ran):
    [POST /transfer]
  who may act still needs a login and a CSRF token
