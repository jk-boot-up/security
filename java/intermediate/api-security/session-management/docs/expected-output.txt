ONE. A session id: random, and never stored as itself.
  BEFORE ENCODING (16 example bytes; real ones are random):
    4f 1a 9c 27 d3 e8 b0 5a 6c 1f 72 e9 a4 d0 3b 8e  (128 bits)
  HOW BASE64URL WORKS (the first 3 bytes, 24 bits):
    01001111 00011010 10011100
    cut into 6 bits a character: 010011=T 110001=x 101010=q 011100=c
  AFTER ENCODING (the id the browser keeps):
    TxqcJ9PosFpsH3LppNA7jg  (22 characters)
  WHAT THE STORE KEEPS (the SHA-256 of the id, in hex):
    c4bf610d8ed59215da093e1a54d4edc0d3d79a2993d7e93511e1b7276b9079e9
  THE REAL IDS (from SecureRandom, never printed):
    a new id is 22 base64url characters: true
    1000 new ids, all different: true
    ana's id contains her name: false (no name, time or counter)
  THE REQUEST (a stolen copy of the store's 3 keys, as cookies):
  THE ANSWER: 0 sessions opened
  THE REQUEST (ana's id, then one character changed):
  THE ANSWERS:
    <ana's id>    allowed
    <changed id>  refused: unknown session
  hashes are compared in constant time; ids are never logged
TWO. A new id at every sign-in and step-up.
  BEFORE ANA SIGNS IN:
    a stranger asks the bank for a visitor id: <planted>
    and gets <planted> into ana's browser
  AFTER SIGN-IN, A BANK THAT KEEPS THE ID:
    ana's id is still <planted>: true
    the stranger sends <planted>: allowed  <- SESSION FIXATION
  AFTER SIGN-IN, A BANK THAT ISSUES A NEW ID:
    ana's id is still <planted>: false; she now has <new>
    the stranger sends <planted>: refused: unknown session
    ana sends <new>: allowed
  AFTER STEP-UP (the password again before a payment):
    ana's id is still <new>: false; she now has <newer>
    <new> is sent: refused: unknown session
    <newer> makes a payment: allowed
THREE. How long a session lives.
  THE SETTINGS:
    idle timeout       15 minutes without a request
    absolute timeout   8 hours after sign-in, busy or not
    password again     for a payment, 5 minutes after it
  IDLE (minutes since ana's last request -> the answer):
    14 -> allowed
    16 -> refused: idle too long, sign in again
    the same id, any time later -> refused: unknown session
  ABSOLUTE (ana stays busy, a request every 10 minutes):
    8 hours = 480 minutes; 480 / 10 = request 48 is at 8:00
    requests 1 to 47 (0:10 to 7:50) -> allowed
    request 48 (8:00) -> refused: session too old, sign in again
  PAYMENTS (minutes since the password was given -> the answer):
    3 -> payment allowed
    6 -> payment asks for the password again
    6 -> reading the account allowed
FOUR. Signing out, everywhere, and the cookie.
  THE SIGN-IN RESPONSE (a real server on this machine):
    status 200
    Set-Cookie: __Host-session=<id>; Path=/; Secure; HttpOnly;
        SameSite=Strict
    problems found: 0
  THE ACCOUNT PAGE, WITH THAT COOKIE: status 200
  THE SIGN-OUT RESPONSE:
    status 200
    Set-Cookie: __Host-session=; Path=/; Secure; HttpOnly;
        SameSite=Strict; Max-Age=0
    the browser forgets the cookie: true
  A COPY MADE BEFORE SIGN-OUT, SENT AGAIN:
    status 401  <- THE SERVER ENDED THE SESSION
  A BANK WHOSE SIGN-OUT ONLY CLEARS THE BROWSER'S COOKIE:
    the copy reads the account: allowed  <- STILL SIGNED IN
  A WEAK COOKIE:
    Set-Cookie: SESSIONID=<id>
  ITS PROBLEMS (4):
    no Secure, no HttpOnly, no SameSite, no __Host- prefix
  ANA IS SIGNED IN ON HER PHONE, LAPTOP AND TABLET:
    sign out everywhere -> 3 sessions ended
    a password change on the laptop -> 2 other sessions ended
      the laptop's new id: allowed
      the laptop's old id: refused: unknown session
    a limit of 3; a fourth sign-in ends the oldest, the phone's
      the phone's id: refused: unknown session
FIVE. The bill.
  THE REQUEST: ana signs in on server A; her next request lands on B
  THE ANSWER FROM B, EACH SERVER WITH ITS OWN MEMORY:
    refused: unknown session  <- NEEDS A SHARED STORE
  THE ANSWER FROM B, BOTH SERVERS SHARING ONE STORE:
    allowed (the -with-spring-session-and-redis version)
  THE REQUEST: a customer reads a statement for 20 minutes
  THE ANSWER:
    refused: idle too long, sign in again  <- THE PRICE
  HOW LONG A STOLEN ID WORKS, AT MOST:
    15 idle minutes, 8 hours in all, or until rotated or ended
  A WRONG PASSWORD STARTS A SESSION: false
