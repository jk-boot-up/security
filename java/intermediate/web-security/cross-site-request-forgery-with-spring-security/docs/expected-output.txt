ONE. CSRF protection switched off, as many tutorials do.
  THE CONFIGURATION (the web chain):
    http.csrf(c -> c.disable())
  ANA SIGNS IN (POST /login):
    302, Set-Cookie: JSESSIONID=<id>; Path=/; HttpOnly
    GET /balance -> 200 balance 1000
  THE REQUEST (a hidden form on https://evil.example):
    POST /transfer   amount=500&to=mallory
    Cookie: JSESSIONID=<Ana's session>  (the browser adds it)
    Origin: https://evil.example
  THE RESPONSE:
    200 sent 500 to mallory  <- ANA NEVER ASKED FOR
    balance: ana 500, mallory 500
TWO. Spring Security's default: a token tied to the session.
  THE CONFIGURATION (the web chain):
    http.csrf(csrf -> csrf
        .ignoringRequestMatchers("/webhooks/**"))
  THE SIGN-IN FORM NEEDS A TOKEN TOO (no forged sign-in):
    POST /login, no token -> 403
    POST /login, with a token -> 302
  THE REQUESTS (POST /transfer, each with Ana's cookie):
    1 Ana, with the token from before she signed in
    2 evil.example, no token
    3 evil.example, a real token from Mallory's session
    4 Ana's own form, with her token (amount=20)
  THE RESPONSES:
    1 403 Forbidden  (the token is renewed at sign-in)
    2 403 Forbidden
    3 403 Forbidden
    4 200 sent 20 to mallory
  HOW THE TOKEN IS MASKED (a new mask on every page):
    the session's token: a UUID of 36 characters: true
    36 random bytes + (token XOR random) = 72 bytes
    as Base64 URL text: 72 / 3 * 4 = 96 characters
    page 1 and page 2 differ: true
    first half XOR second half: the same token on both: true
  ONE BYTE OF IT ('a' and a random byte 0x5c):
    0x61 XOR 0x5c = 0x3d is sent
    0x3d XOR 0x5c = 0x61 ('a') again
  THE REQUESTS (POST, each with Ana's cookie):
    5 /transfer, the token masked by hand (amount=20)
    6 /logout, no token
    7 /logout, with her token
  THE RESPONSES:
    5 200 sent 20 to mallory
    6 403    7 302  (logging out is a state change too)
    balance: ana 960, mallory 40
THREE. A single-page app: the token in a readable cookie.
  THE CONFIGURATION (the web chain):
    csrf.csrfTokenRepository(
        CookieCsrfTokenRepository.withHttpOnlyFalse())
  THE COOKIE THE BANK SETS:
    Set-Cookie: XSRF-TOKEN=<token>; Path=/
    HttpOnly: false, so the page's script can read it,
    and so could injected script (cross-site scripting)
  THE REQUESTS (POST /transfer; the browser adds both cookies):
    1 evil.example, no X-XSRF-TOKEN header
    2 evil.example, the header = Mallory's cookie value
    3 the bank's script copies the cookie into the header
  THE RESPONSES (the header must equal the cookie):
    1 403 Forbidden
    2 403 Forbidden
    3 200 sent 20 to mallory
    balance: ana 980, mallory 20
  evil.example cannot copy the cookie: a page reads only
  its own site's cookies
FOUR. What the default does not cover.
  THE REQUESTS (Ana is signed in; no CSRF token is sent):
    1 evil.example: POST /webhooks/payments, no signature
    2 the payment provider: the same, with X-Signature
    3 evil.example link: GET /legacy/move?to=mallory&amount=100
    4 evil.example link: GET /transfer?to=mallory&amount=100
  THE RESPONSES:
    1 401 bad signature  (no token needed: it checks a signature)
    2 200 payment noted
    3 200 sent 100 to mallory  <- GET IS NEVER CHECKED
    4 405  (the route needs POST)
    balance: ana 900, mallory 100
  THE CONFIGURATION, AFTER ONE CHANGE TO PASS A TEST:
    csrf.ignore=/webhooks/**,/transfer
  THE REQUEST: evil.example, POST /transfer, no token
  THE RESPONSE:
    200 sent 500 to mallory  <- DEFENCE UNDONE
FIVE. The bill.
  THE SESSION COOKIE BY DEFAULT:
    Set-Cookie: JSESSIONID=<id>; Path=/; HttpOnly
    HttpOnly: true    SameSite set: false
  THE API REQUESTS (POST /api/transfer; no session at all):
    1 evil.example: Ana's cookie, no Authorization header
    2 Ana's app: Authorization: Basic YW5hOmxhYi1wYXNzd29yZA==
      (Base64 of ana:lab-password)
  THE RESPONSES:
    1 401 Unauthorized
    2 200 sent 20 to mallory
  a browser never adds a header it was not given
  EACH STATE-CHANGING ROUTE (evil.example, no token):
    /transfer 403   /logout 403   /login 403
    3 of 3 refused
  WITH server.servlet.session.cookie.same-site=lax:
    Set-Cookie: JSESSIONID=<id>; Path=/; HttpOnly;
                SameSite=Lax
    one more layer; the token is still needed
