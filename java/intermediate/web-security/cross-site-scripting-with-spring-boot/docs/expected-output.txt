ONE. Thymeleaf escapes by default.
  Ana's review is the text <b>Great boots</b>, written with th:text
  the page answers 200, and the review is written as: &lt;b&gt;Great boots&lt;/b&gt;
  bold elements on the page: 0, so the review stayed text
  nothing had to be remembered: th:text is the ordinary way to write a value
TWO. th:utext, the one switch that turns escaping off.
  the same review written with th:utext: <b>Great boots</b>
  bold elements on the page: 1, and the shop wrote none  <- THE REVIEW BECAME PART OF THE PAGE
  th:utext means unescaped text: it is for markup the shop wrote itself, never for anything a customer typed
  a search of the templates for th:utext finds every place this can happen: 1 of 2 templates, and a test fails if another one appears
THREE. The other places a value can go.
  in an attribute, with th:attr: Ben's fit note reads back whole: Fits 5" boots  (true)
  in a link, with @{/search(q=...)}: /search?q=size%205%20%26%20up
  the search text is one parameter, and its & did not start a second one: true
  in a script, with th:inline="javascript": const note = "It's \"great\""
  each value went through the escaping for its own place, chosen by how it was written in the template
FOUR. A strict Content-Security-Policy from Spring Security, with a fresh nonce for every page.
  the product page answers with a policy: true
  the policy names a nonce, and the shop's own script carries the same one: true
  the next page has a different nonce: true
  the shop's script may run: true
  a script that slipped in without the nonce may run: false  <- A SECOND LINE OF DEFENCE
  the nonce comes from a filter that runs before Spring Security writes its headers, so the header and the page always agree
FIVE. The bill.
  the session cookie is HttpOnly: true, and SameSite=Strict: true
  escaping by default protects only the values written through it: th:utext, and HTML built in Java code, skip it
  a value placed in an event handler or a style needs more than escaping: keep customer text out of those places
  Spring Security writes a fixed policy unless the application supplies the nonce, as this store does with one small filter
