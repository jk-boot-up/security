ONE. Thymeleaf escapes by default.
  THE VALUE (Ana's review, put in the model):
    <b>Great boots</b>
  THE TEMPLATE LINE (product.html):
    <p class="review" th:text="${review}">review</p>
  THE PAGE (as the server sent it, status 200):
    <p class="review">&lt;b&gt;Great boots&lt;/b&gt;</p>
  THE RESULT (the elements a browser finds):
    html head meta title body h1 p p a script
    b elements: 0, so the review stayed text
  nothing had to be remembered: th:text is the ordinary way
TWO. th:utext, the one switch that turns escaping off.
  THE TEMPLATE LINE (product-unescaped.html):
    <p class="review" th:utext="${review}">review</p>
  THE PAGE (as the server sent it, status 200):
    <p class="review"><b>Great boots</b></p>
  THE RESULT (the elements a browser finds):
    html head meta title body h1 p b
    b elements: 1, and the shop wrote none  <- THE PAGE CHANGED
  THE GUARD (a search of the templates for th:utext):
    product.html             no
    product-unescaped.html   uses it
    a test fails if any other template starts to use it
  th:utext is for markup the shop wrote, never for customer text
THREE. The other places a value can go.
  THE VALUES (put in the model):
    fitNote     Fits 5" boots
    search      size 5 & up
    scriptNote  It's "great"
  THE TEMPLATE (how each one is written):
    th:attr="data-fit=${fitNote}"
    th:href="@{/search(q=${search})}"
    th:inline="javascript" and [[${scriptNote}]]
  THE PAGE (what Thymeleaf wrote for each):
    data-fit="Fits 5&quot; boots"
    href="/search?q=size%205%20%26%20up"
    const note = "It's \"great\"";
  HOW THE CHARACTERS WERE WRITTEN:
    " -> &quot; in an attribute, \" in a script string
    space -> %20, & -> %26 in a link (& is 38 = 2 x 16 + 6)
  THE RESULT (what the browser reads back):
    fit note    Fits 5" boots  (whole: true)
    link        parameters: 1, so the & stayed text
    script      one string, no early end: true
FOUR. A strict Content-Security-Policy from Spring Security.
  THE REQUEST:
    GET /product
  THE RESPONSE (the nonce shown as <nonce>):
    status 200, and the header Content-Security-Policy:
      default-src 'self'
      script-src 'nonce-<nonce>' 'strict-dynamic'
      object-src 'none'
      base-uri 'none'
      frame-ancestors 'none'
    Set-Cookie: JSESSIONID=<id>; Path=/; HttpOnly; SameSite=Strict
    <script nonce="<nonce>">
  HOW THE NONCE GETS THERE (one request):
    NonceFilter: 16 random bytes, written in Base64
    16 bytes -> 6 groups of up to 3 -> 24 characters
    it runs before Spring Security writes its headers
    request attribute cspNonce, read by the header and the page
    this page's nonce: 24 characters
    the header's nonce is the script's nonce: true
    the next page's nonce differs: true
  WHICH SCRIPTS MAY RUN (what a browser decides):
    the shop's script, with the nonce   yes
    a script without the nonce          no  <- BLOCKED
    the cookie is HttpOnly: true, SameSite=Strict: true
