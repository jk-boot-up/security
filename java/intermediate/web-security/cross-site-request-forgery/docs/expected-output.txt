ONE. A request Ana did not intend.
  ANA LOGS IN (POST https://bank.example/login):
    200 welcome ana
    Set-Cookie: sid=<id>; Path=/; Secure; HttpOnly; SameSite=None
    balance: ana 1000, mallory 0
  THE REQUEST (a hidden form on https://evil.example):
    POST https://bank.example/transfer
    amount=500&to=mallory
    Cookie: sid=<Ana's id>
    Origin: https://evil.example
    Sec-Fetch-Site: cross-site
  THE RESPONSE:
    200 sent 500 to mallory  <- ANA NEVER ASKED FOR
    balance: ana 500, mallory 500
  the browser added the cookie because the request went
  to the bank: it proves who asks, not what Ana meant
TWO. A token in every form.
  THE BANK'S FORM (GET /transfer-form, as Ana):
    <input type="hidden" name="csrf" value="<Ana's token>">
  HOW THE TOKEN IS MADE:
    32 random bytes from SecureRandom = 256 bits
    Base64 URL text, 6 bits a character: 256 / 6 = 42.7 -> 43
    Ana's token: 43 characters, kept in her session
  THE REQUESTS (POST /transfer, each with Ana's cookie):
    1 the bank's form  csrf=<Ana's token>      amount=20
    2 evil.example     no csrf field           amount=500
    3 evil.example     csrf=<Mallory's token>  amount=500
  THE CHECK (the sent token against Ana's session token):
    1 equal (MessageDigest.isEqual, in constant time)
    2 missing
    3 not equal: it was made for Mallory
  THE RESPONSES:
    1 200 sent 20 to mallory
    2 403 no form token
    3 403 the form token does not belong to this session
    balance: ana 980, mallory 20
  evil.example cannot read Ana's form: a browser does not let
  one site read another site's pages
THREE. SameSite cookies.
  HOW THE BROWSER FINDS THE SITE (the last two labels):
    https://evil.example  -> evil.example
    https://bank.example  -> bank.example
    the sites differ, so the request is cross-site
  THE RULE FOR A CROSS-SITE REQUEST:
    None: the cookie goes, if it is also Secure
    Lax: the cookie goes only on a top-level GET link
    Strict: the cookie never goes
  THE REQUESTS (Ana's cookie has SameSite=Lax):
    1 a forged POST from evil.example  cookie: not sent
    2 a link (GET) on evil.example     cookie: sent
    3 the bank's own form (POST)       cookie: sent
  THE RESPONSES:
    1 401 not logged in
    2 200 balance 1000
    3 200 sent 20 to mallory
  THE REQUESTS (SameSite=Strict):
    4 a link (GET) on evil.example     cookie: not sent
    5 Ana types the bank's address     cookie: sent
  THE RESPONSES:
    4 401 not logged in, so Ana looks logged out
    5 200 balance 1000
  THE REQUEST (no SameSite: a modern browser reads it as Lax):
    6 a forged POST from evil.example  cookie: not sent
  THE RESPONSE:
    6 401 not logged in
FOUR. Where the request came from, and GET.
  HOW THE BROWSER PICKS Sec-Fetch-Site (a page -> bank.example):
    https://bank.example          same origin  -> same-origin
    https://reviews.bank.example  same site    -> same-site
    https://evil.example          other site   -> cross-site
  THE REQUESTS (POST /transfer; the bank reads these headers):
    1 forged, modern browser  Sec-Fetch-Site: cross-site
    2 the bank's own form     Sec-Fetch-Site: same-origin
    3 forged, older browser   Origin: https://evil.example
  THE RESPONSES:
    1 403 Sec-Fetch-Site is cross-site, not same-origin
    2 200 sent 20 to mallory
    3 403 Origin is https://evil.example, not the bank
  with neither header, only the token is left
  THE REQUEST (a link on evil.example; the cookie is Lax):
    GET https://bank.example/transfer?to=mallory&amount=100
    Cookie: sid=<Ana's id>
    Sec-Fetch-Site: cross-site
  THE RESPONSES:
    a bank that moves money on GET:
      200 sent 100 to mallory  <- A LINK MOVED MONEY
    a bank that needs POST for a transfer:
      405 a transfer needs POST
FIVE. The bill.
  THE REQUESTS (POST /transfer):
    1 older browser, SameSite=Lax only, from evil.example
    2 SameSite=Strict only, from reviews.bank.example
    3 the same as 2, with tokens switched on
    4 Ana, from a bank page that forgot the token
  THE RESPONSES:
    1 200 sent 500 to mallory  <- SameSite IS IGNORED
    2 200 sent 500 to mallory  <- SAME SITE: COOKIE SENT
    3 403 no form token
    4 403 no form token  <- ANA HERSELF IS REFUSED
  THE API REQUESTS (POST /api/transfer):
    5 a script on evil.example, no Authorization header
    6 Ana's app: Authorization: Bearer <API token>
  THE RESPONSES:
    5 401 no API token
    6 200 sent 20 to mallory
  a browser never adds that header by itself, so a bearer
  token is safe from CSRF unless it is kept in a cookie
