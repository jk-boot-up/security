ONE. A review that changes the page.
  Ana's review is the text <b>Great boots</b>, pasted into the page as it is
  bold elements on the page: 1, and the shop wrote none  <- THE REVIEW BECAME PART OF THE PAGE
  the browser cannot tell the shop's markup from the customer's, so a script in a review would run as the shop's own
  that script could read the page, act as the signed-in customer, and send what it finds elsewhere
TWO. Encoding for the place the text goes.
  between tags: &lt;b&gt;Great boots&lt;/b&gt;
  in a quoted attribute: Fits 5&quot; boots
  in a URL parameter: size%205%20%26%20up
  in a script string: It\u0027s \u0022great\u0022
  the encoded page: bold elements 0, and Ben's fit note reads back whole: Fits 5" boots
  every value shows as the text the customer typed, and none of it is read as markup
THREE. Why filtering input is not the fix.
  an honest review: Warm & dry, price < 20 & > 10
  after a filter that deletes < and >: Warm & dry, price  20 &  10  <- THE CUSTOMER'S WORDS ARE CHANGED
  encoded instead, the page shows it exactly: true
  the filter keeps the quote in Ben's fit note, so the attribute ends early and reads: Fits 5  <- THE FILTER DID NOT KNOW THE CONTEXT
  a filter guesses at every place text will go; an encoder is chosen for the one place it does go
FOUR. A strict Content-Security-Policy, with a fresh nonce for every page.
  the product page answers 200 with a policy: true
  the policy names a nonce, and the shop's own script carries it: true
  the nonce is 24 characters of random text, and the next page has a different one: true
  the shop's script may run: true
  a script that slipped in without the nonce may run: false  <- A SECOND LINE OF DEFENCE
  the same script with no policy at all: true
  a policy with 'unsafe-inline' and no nonce: true, so it protects nothing
  the session cookie is HttpOnly, so a script cannot read it: true
FIVE. The bill.
  this one page writes untrusted text into 4 kinds of place, and each needs its own encoder; one forgotten place is enough
  the policy needs care: every inline script must carry the nonce, and every new source must be added on purpose
  the nonce must be new for every response, or a page from yesterday hands an attacker today's key
  in practice, a template engine that encodes by default does the first part: see the tools version of this project
