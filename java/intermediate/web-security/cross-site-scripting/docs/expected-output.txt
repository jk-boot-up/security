ONE. A review that changes the page.
  THE REVIEW (typed by Ana):
    <b>Great boots</b>
  THE PAGE AS BUILT (the review pasted in as it is):
    <div class="review" data-fit="true to size">
      <p><b>Great boots</b></p>
      <span>Ana</span></div>
  THE RESULT (the elements a browser finds):
    plain text    html body h1 div p span
    Ana's review  html body h1 div p b span
    1 b element the shop never wrote  <- THE PAGE CHANGED
  THE REVIEW (typed by Eve):
    <script>steal(document.cookie)</script>
  THE RESULT:
    script elements: 1  <- IT RUNS AS THE SHOP'S OWN CODE
    it could act as the signed-in customer
TWO. Encoding for the place the text goes.
  BEFORE ENCODING (the place, and the customer's text):
    between tags      <b>Great boots</b>
    quoted attribute  Fits 5" boots
    URL parameter     size 5 & up
    script string     It's "great"
  AFTER ENCODING:
    between tags      &lt;b&gt;Great boots&lt;/b&gt;
    quoted attribute  Fits 5&quot; boots
    URL parameter     size%205%20%26%20up
    script string     It\u0027s \u0022great\u0022
  HOW EACH CHARACTER IS ENCODED:
    char   HTML    URL  script
    <      &lt;    %3C  \u003c
    >      &gt;    %3E  \u003e
    &      &amp;   %26  \u0026
    "      &quot;  %22  \u0022
    '      &#39;   %27  \u0027
    space  space   %20  space
    " is character 34 = 2 x 16 + 2, so 22 in hex
  THE ENCODED PAGE (Ben's review):
    <div class="review" data-fit="Fits 5&quot; boots">
      <p>Warm &amp; dry, price &lt; 20 &amp; &gt; 10</p>
      <span>Ben</span>
      <a href="/reviews?author=Ben">more</a></div>
  THE RESULT (what the browser reads back):
    fit note     Fits 5" boots
    review text  Warm & dry, price < 20 & > 10
    Ana's review, encoded: b elements 0
THREE. Why filtering input is not the fix.
  BEFORE THE FILTER (Ben's review, Eve's fit note):
    Warm & dry, price < 20 & > 10
    x" onclick="steal()
  AFTER A FILTER THAT DELETES < AND >:
    Warm & dry, price  20 &  10  <- HONEST WORDS CHANGED
    x" onclick="steal()  <- THE ATTACK IS UNTOUCHED
  THE PAGE AS BUILT (the filtered fit note pasted in):
    <div class="review" data-fit="x" onclick="steal()">
  THE RESULT (the attributes a browser finds on the div):
    class=review  data-fit=x  onclick=steal()
    <- A SCRIPT RUNS WHEN THE REVIEW IS CLICKED
  ENCODED INSTEAD (the div's data-fit attribute):
    data-fit="x&quot; onclick=&quot;steal()"
  THE RESULT:
    class=review  data-fit=x" onclick="steal()
    Ben's words read back exactly: true
  a filter guesses; an encoder is chosen for the place
FOUR. A strict Content-Security-Policy, with a fresh nonce.
  THE REQUEST (to the shop, served for real on this machine):
    GET /product
  THE RESPONSE (its nonce is shown as <nonce>):
    status 200, and the header Content-Security-Policy:
      default-src 'self'
      script-src 'nonce-<nonce>' 'strict-dynamic'
      object-src 'none'
      base-uri 'none'
      frame-ancestors 'none'
    Set-Cookie: session=demo-24; Path=/;
      HttpOnly; Secure; SameSite=Lax
    <script nonce="<nonce>">var firstReviewer = "Ana";</script>
  HOW THE NONCE IS MADE:
    16 random bytes = 128 bits, written in Base64
    Base64 turns every 3 bytes into 4 characters
    16 bytes -> 6 groups (the last one short) -> 24 characters
    example, bytes 00 01 02 ... 0f -> AAECAwQFBgcICQoLDA0ODw==
    this page's nonce: 24 characters; the next page's differs: true
    the script's nonce is the policy's nonce: true
  WHICH SCRIPTS MAY RUN (what a browser decides):
    the shop's script, with the nonce     yes
    Eve's script, without a nonce         no  <- BLOCKED
    the same script, with no policy       yes
    'unsafe-inline' and no nonce          yes  <- PROTECTS NOTHING
    the cookie is HttpOnly, so no script can read it: true
