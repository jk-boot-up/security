ONE. A cart in a cookie works for honest customers.
  THE CART (code, quantity, price per unit in cents):
    KTL-001  x2  2500
    PAN-002  x1  4200
  THE COOKIE (the cart serialized by Java, then Base64):
    rO0ABXNyACJjb20uamsuZXhw...  (398 characters)
  HOW IT STARTS (the first six bytes, in hex):
    AC ED 00 05 73 72  -> Base64 rO0ABXNy
    AC ED = the serialization magic, 00 05 = version 5
    73 = a new object, 72 = its class description
  THE CLASSES THE COOKIE NAMES (each one is built):
    Cart, ArrayList, Object[], Cart$Line
  THE RESULT:
    2 lines, total 9200 cents
    2 x 2500 + 1 x 4200 = 9200
TWO. The cookie decides what the server builds.
  THE FORGED CART (written by the customer):
    KTL-001  x2  1
  THE RESULT:
    1 line, total 2 cents  <- A FORGED PRICE
    2 x 1 = 2
  THE FORGED COOKIE (not a cart at all):
    a TempCleaner, path = <a marker file on the server>
  THE MARKER FILE BEFORE READING:
    exists: true
  THE CLASSES THE COOKIE NAMES (each one is built):
    TempCleaner
  THE RESULT:
    refused: the cookie is not a cart
    marker file exists afterwards: false  <- IT ALREADY RAN
  checking the type after readObject is too late
THREE. An allow-list filter names the classes of a cart.
  THE ALLOW-LIST (checked before each class is built):
    Cart Cart$Line ArrayList Object String
    Record Number Long Integer
    maxdepth=5 maxrefs=100
    maxarray=100 maxbytes=2000 !*  (!* = refuse the rest)
  THE HONEST CART -> THE FILTER'S ANSWERS:
    Cart       -> ALLOWED
    ArrayList  -> ALLOWED
    Object[]   -> ALLOWED
    Cart$Line  -> ALLOWED
    -> 2 lines, total 9200 cents
  THE TEMPCLEANER COOKIE -> THE FILTER'S ANSWER:
    TempCleaner -> REJECTED
  THE RESULT:
    refused: class refused by the filter
    marker file exists afterwards: true
  THE FORGED PRICE -> THE FILTER'S ANSWERS:
    Cart, ArrayList, Object[], Cart$Line -> all ALLOWED
    -> 1 line, total 2 cents  <- STILL ACCEPTED
  a filter stops unknown classes, not lies
FOUR. Data only: product codes and quantities, signed.
  THE COOKIE TEXT (no classes, no prices):
    v1;KTL-001x2;PAN-002x1
  THE BODY (the text in Base64):
    djE7S1RMLTAwMXgyO1BBTi0wMDJ4MQ
  THE SIGNATURE (HMAC-SHA-256 of the body, server's key):
    XJD4Phz3L9opviZkyUfrNcyTrXkZnLzk2OjIBaf-zbE
  THE COOKIE IS body.signature
  THE RESULT (signature checked first, then prices looked up):
    KTL-001  x2  x 2500 = 5000
    PAN-002  x1  x 4200 = 4200
    2 lines, total 9200 cents
  THE QUANTITY CHANGED BY THE CUSTOMER (x2 -> x9):
    v1;KTL-001x9;PAN-002x1  (the new text)
    the server's HMAC of the new body:
      21AurWKCMA7UyV16wZ3AKLUrepHf-llmQ9FornieabU
    the signature in the cookie (unchanged):
      XJD4Phz3L9opviZkyUfrNcyTrXkZnLzk2OjIBaf-zbE
    -> refused: bad signature
  THE OTHER FORGED COOKIES:
    a serialized object -> refused: not a signed cookie
    unsigned text       -> refused: bad signature
