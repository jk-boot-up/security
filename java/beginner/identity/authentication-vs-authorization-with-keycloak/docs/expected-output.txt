TWO. Inside a token, and its signature.
  BEFORE DECODING (the token as sent, 642 characters):
    eyJhbGciOiJSUzI1NiJ9.eyJzdWIiOiJhbmEiLCJhdWQ...
  AFTER DECODING (base64url, split at the two dots):
    header     {"alg":"RS256"}
    claims     iss          http://login.shop.example/realms/shop
               sub          ana
               aud          shop-api
               azp          shop-web
               preferred_username ana
               realm_access {"roles":["customer"]}
               iat          1767258301 = 2026-01-01 09:05:01Z
               exp          1767258601 = 2026-01-01 09:10:01Z
               jti          token-2
    signature  256 bytes, made with the private key
  STEP 1. THE SIGNED TEXT = header + "." + claims, as sent:
    eyJhbGciOiJSUzI1NiJ9.eyJzdWIiOiJhbmEiLCJhdWQ...
  STEP 2. ITS HASH = SHA-256(signed text), 32 bytes:
    hash     a1ec3b27 76ab890b 126b93e6 e7602ef4
             9266e7f3 570f2f2b 97992666 074a90a4
  STEP 3. OPEN THE SIGNATURE: signature ^ e mod n (public key)
    e = 65537, n has 2048 bits, the result has 256 bytes:
    0001, then 202 bytes of ff, then 00
    3031300d 06096086 48016503 04020105 000420 = "SHA-256"
    last 32  a1ec3b27 76ab890b 126b93e6 e7602ef4
             9266e7f3 570f2f2b 97992666 074a90a4
  STEP 4. COMPARE the two hashes: true
  BEFORE TAMPERING (roles [customer]): GET /me 200
  AFTER TAMPERING (customer -> admin, same signature):
    hash     4b680136 69a41069 0c45e69e 0b6c8b1d
             e6244c67 c42b8073 1f6ff516 491bad93
    in sig   a1ec3b27 76ab890b 126b93e6 e7602ef4
    compare  false: GET /me 401  <- BROKEN

FOUR. A real signature is not enough.

FIVE. The roles in a token are a copy.
  BEFORE THE DEMOTION (root's token says [admin]):
    GET /admin/report  200  sales
  root is demoted to customer in the login server's directory
  AFTER THE DEMOTION:
    the same token:     GET /admin/report  200  <- ONLY A COPY
    301 seconds later:  GET /admin/report  401  expired
    a new token says [customer]:
                        GET /admin/report  403
                        GET /me            200
  the stale window is at most the token's lifetime: 300 s
SIX. Ending a token early, and the bill.
  BEFORE REVOKING (root's admin token, jti token-10):
    GET /admin/report  200  sales
    GET /admin/report  200  sales
  token-10 is put on the revocation list
  AFTER REVOKING:
    GET /admin/report  401  <- ENDED AT ONCE
  THE BILL:
    the list was read 3 times for 3 requests: every time
    without a list: no call, but the token works until expiry
    refresh tokens: long sessions with short access tokens
    the login server: one more system to run, patch, back up
