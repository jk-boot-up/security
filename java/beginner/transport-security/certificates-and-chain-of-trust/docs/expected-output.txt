ONE. A chain of three certificates.
  root:         CN=Example Root CA, signed by itself: true
  intermediate: CN=Example Issuing CA, signed by CN=Example Root CA, may issue certificates: true
  server:       CN=shop.example, signed by CN=Example Issuing CA, may issue certificates: false
  each certificate holds its owner's public key and the issuer's signature over it, both as plain data
  the signature algorithm is SHA256withECDSA, and anyone can check it with the issuer's public key
TWO. The browser's check.
  the server sends its own certificate and the intermediate; the browser already trusts the root
  the chain is accepted: true
  the certificate is for shop.example: true
  the certificate is for evil.example: false
  a wildcard *.example stands for exactly one label: shop.example true, a.b.example false
THREE. Three reasons to refuse.
  a certificate that ended on 2024-12-31, checked on 2026-01-01: accepted false, reason EXPIRED
  a certificate for shop.example from an authority the browser does not trust: accepted false, reason INVALID_SIGNATURE
  the rogue root has the same name as the real one: true, so names prove nothing, only keys do
  the same valid chain, shown to a visitor who meant evil.example: chain accepted true, name matches: false
  so a client must check the chain and the name, and both are separate checks
FOUR. Changed certificates, and certificates that overstep.
  one letter of the name changed (CN=shop.examplE): it still parses, accepted false, reason INVALID_SIGNATURE
  the shop's server key signs a certificate for other.example: accepted false, reason INVALID_KEY_USAGE
  a server certificate says it is not a CA, so what it signs is not trusted
  the intermediate's limit on further authorities below it (path length): 0
FIVE. Revocation, and the bill.
  someone steals the intermediate's private key and issues their own certificate for shop.example
  the forged chain is accepted: true  <- A STOLEN CA KEY BREAKS EVERYTHING BELOW IT
  the shop's own certificate put on the revocation list: accepted false, reason REVOKED
  the intermediate put on the list: the shop's chain accepted false, the forged chain accepted false
  but a list only works if the client gets the latest one: real clients use CRLs, OCSP, short lifetimes, or all three
  trusting a root is a decision: it may vouch for any name, so keep the store small and keep CA keys offline or in hardware
