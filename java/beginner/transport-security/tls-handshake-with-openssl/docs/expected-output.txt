ONE. A real TLS server and client on this machine.
  the server listens on the loopback address; the client connects by the name shop.example.test
  handshake works: true, agreed protocol: TLSv1.3
  agreed cipher suite: TLS_AES_256_GCM_SHA384
  the server answered: received: order=A-1001
  two engines wired together in memory agree the same suite: true
  anything that speaks TLS can take the client's place, so the tests let the openssl program do it
TWO. Giving the certificate and key to other programs.
  the certificate file starts with -----BEGIN CERTIFICATE----- and ends with -----END CERTIFICATE-----
  the key file starts with -----BEGIN PRIVATE KEY----- and ends with -----END PRIVATE KEY-----
  the certificate names CN=shop.example.test and the key type is EC
  the key file is readable by its owner only: true
  PEM is only Base64 of the same bytes, so openssl reads what Java wrote and Java reads what openssl writes
  the key file holds the private key in the clear  <- PROTECT IT LIKE A PASSWORD
THREE. Who is on the other end.
  the shop's own certificate, name shop.example.test: handshake works: true
  an impostor with the same name but a certificate the client does not trust: handshake works: false  <- THE CLIENT REFUSES
  the shop's real certificate, but the client asked for another.example.test: handshake works: false  <- THE NAME MUST MATCH
  openssl s_client checks the same two things when given -verify_return_error and -verify_hostname
FOUR. Versions: what each side offers.
  a client that offers only TLS 1.2 to a server that allows the defaults: handshake works: true
  the agreed protocol is TLSv1.2
  the same client against a server that allows only TLS 1.3: handshake works: false
  a client that offers only TLS 1.1: handshake works: false  <- OLD VERSIONS ARE SWITCHED OFF
  openssl s_client -tls1_2 and -tls1_1 make the same offers, and the tests check what it is told
FIVE. Checking from the outside, and the bill.
  to check a server with another program, run: openssl s_client -connect HOST:PORT -servername NAME -CAfile cert.pem -verify_hostname NAME -verify_return_error
  to serve with another program, run: openssl s_server -accept PORT -cert cert.pem -key key.pem
  the bill: a second implementation catches mistakes in the first, but only the settings that you actually pass are checked
  openssl without -verify_return_error prints the problem and carries on, so a script must check the exit status and the verification line
  a private key written to a file for another program is one more copy to protect
