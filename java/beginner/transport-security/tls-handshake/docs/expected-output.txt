ONE. A sniffer on the wire, without and with TLS.
  without TLS the order is sent as it is, and the sniffer sees the card number: true
  with TLS the sniffer sees a record of type 23 (application data) and the card number: false
  the record is not larger than the order plus a few dozen bytes of header, padding and tag: true
TWO. The handshake.
  the client speaks first, with a handshake record (type 22) called ClientHello
  the ClientHello is not encrypted, because no key exists yet, so the sniffer reads the name of the site: true
  the server answers with a handshake record (type 22) called ServerHello, which chooses the protocol and cipher
  after the ServerHello the rest of the handshake is encrypted: the certificate is hidden from the sniffer: true
  agreed protocol: TLSv1.3
  agreed cipher suite: TLS_AES_256_GCM_SHA384
  both sides now share keys that were never sent over the wire
THREE. Who is on the other end.
  the shop's own certificate, name shop.example.test: handshake works: true
  an impostor with the same name but a certificate the client does not trust: handshake works: false  <- THE CLIENT REFUSES
  the shop's real certificate, but the client asked for another.example.test: handshake works: false  <- THE NAME MUST MATCH
  a certificate proves a key belongs to a name, because someone the client trusts vouched for it
FOUR. Protecting the data.
  the server opens an untouched record and gets the order back: true
  the same order in two connections gives different bytes on the wire, because each has fresh keys: true
  one changed bit in a record: refused  <- TLS PROTECTS INTEGRITY AS WELL AS SECRECY
  the keys of each connection are made fresh from temporary key pairs, so a stolen server key cannot open recorded traffic
FIVE. Settings, and the bill.
  a client that only offers TLS 1.0: handshake works: false  <- OLD VERSIONS ARE SWITCHED OFF
  a client that offers only TLS 1.2: handshake works: true, agreed protocol: TLSv1.2
  the same client against a server that requires TLS 1.3: handshake works: false
  the bill: certificates must be obtained and renewed, the handshake costs a round trip and some computing, and the keys must be kept safe
  TLS protects the connection between two ends, not what the ends do with the data, and the name of the site and the sizes of messages still show
