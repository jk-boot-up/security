ONE. nginx ends the TLS for the shop.
  a Java client that trusts the demo root asks https://shop.example.test/ and gets 200 over TLSv1.3
  HTTP/2 was agreed during the handshake: yes
  the five security headers score 5 of 5, and the Server header says just nginx
  behind nginx the application, on a plain local port, answered: app saw proto=https client=
TWO. Which TLS versions the shop allows.
  nginx set to TLS 1.3 only: a client limited to TLS 1.2 is refused
  the same server and a TLS 1.3 client: TLSv1.3
  nginx set to allow TLS 1.2 as well, with three strong ciphers: the TLS 1.2 client gets TLSv1.2
  a TLS 1.3 client on the same server still gets TLSv1.3
  allow TLS 1.2 only while customers still need it, and keep the list of ciphers short
THREE. The plain port, the redirect and HSTS.
  GET http://shop.example.test/orders?id=7 answers 301 and Location https://shop.example.test/orders?id=7
  the plain answer carries HSTS: no (a browser ignores HSTS sent over plain HTTP)
  the HTTPS answer carries HSTS: max-age=63072000; includeSubDomains
  the very first visit is still plain, so HSTS protects every visit after it, and preloading protects the first
FOUR. Who the client trusts, and who the server trusts.
  the JDK's own list of trusted roots does not know the demo root: refused
  with the demo root trusted, the right name: accepted
  with the demo root trusted, but connecting by the address 127.0.0.1: refused  <- THE NAME IN THE CERTIFICATE MUST MATCH
  a server with the right name and a certificate signed by nobody trusted: refused
  with ssl_verify_client on, a client with no certificate: refused
  with Ana's certificate: 200 and app saw proto=https client=CN=Ana the customer
  Ana adds a header claiming to be the admin: app saw proto=https client=CN=Ana the customer  <- NGINX OVERWRITES HEADERS IT SETS ITSELF
FIVE. The proxy trap, a config check and a score.
  a plain request claims X-Forwarded-Proto: https and nginx passes it on: app saw proto=https client=  <- THE APP BELIEVES THE CONNECTION IS SECURE
  the same request when nginx sets the header from what it saw: app saw proto=http client=
  nginx -t on the careful configuration: syntax ok
  nginx -t when the certificate file is missing: refused before any customer sees it
  the careful configuration scores 7 of 7 on the TLS habits
  a typical copied configuration scores 1 of 7
  OCSP stapling is for certificates from a public authority and needs the server to reach it, so it is described and not run here
