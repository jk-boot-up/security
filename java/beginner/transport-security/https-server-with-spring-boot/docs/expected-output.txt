ONE. TLS from an SSL bundle.
  the server's certificate and key, and TLS 1.3 only, are set in properties: server.ssl.bundle=shop and a bundle that names the keystore
  a client built from a bundle that trusts only the demo root asks for /products: 200 over TLSv1.3
  the same call through Spring's RestClient: kettle, toaster, lamp
  the same server reached by another name, evil.example.test: refused  <- THE NAME ON THE CERTIFICATE MUST MATCH
  a client that offers only TLS 1.2: refused
  a client that uses the JDK's default trust and not the bundle: refused  <- THE DEMO ROOT IS NOT IN THE JDK'S LIST
TWO. Redirect, HSTS and secure cookies.
  a request to the plain HTTP port is answered with 302 pointing to an https address: true, and the body is empty: true
  the plain answer carries Strict-Transport-Security: false
  the HTTPS answer carries Strict-Transport-Security: max-age=31536000 ; includeSubDomains
  the session cookie is Secure: true, HttpOnly: true, SameSite=Strict: true
  the client would send that cookie over HTTPS: true, over plain HTTP: false
THREE. Renewing a certificate without a restart.
  the certificate served matches the file on disk: true
  the file is replaced with the renewed certificate and the server is not restarted
  the certificate served has changed: true, and now matches the new file: true
  clients that trust the root still connect without any change: ok (200)
FOUR. Mutual TLS: the server checks the client too.
  the server is told server.ssl.client-auth=need and the bundle gets a trust store for client certificates
  Ana's client presents a certificate signed by the demo root: 200, the server saw: CN=Ana the customer
  a client with no certificate: refused
  a client whose certificate is signed by nobody: refused
  this identifies a machine or an app, not a person who types a password, so it suits service-to-service calls
FIVE. What Spring leaves to you.
  /actuator/health: 404  <- the actuator is not on the class path, so nothing extra is exposed
  a failing page answers 500 and its body mentions the internal detail: false
  a Server header that names the software: false
  configuration is short, and that is the risk: a wrong property is as silent as a right one, so check the result from outside
  the private key sits in a file the server can read, so protect it, rotate it, and renew before it expires
