ONE. An HTTP message is just text.
  a customer's browser sends 82 characters: a request line, headers, a blank line, and a body
  parsed: method POST, target /orders, Host shop.example, body 17 bytes
  written out again it is the same text: true
  every header is only a line of text that the sender chose, so the server must check it
TWO. Messages that two programs could read differently.
  Content-Length and Transfer-Encoding together: refused (both Content-Length and Transfer-Encoding)
  the same, with TRANSFER-ENCODING in capitals, on a machine set to Turkish: refused (both Content-Length and Transfer-Encoding)  <- HEADER NAMES ARE LOWER-CASED WITHOUT THE LOCALE
  two different Content-Length headers: refused (two different Content-Length headers)
  a space before the colon in a header name: refused (a header name with a space or odd character: 'Content-Length ')
  a body longer than its Content-Length, with a second request hidden after it: refused (Content-Length says 4 bytes but 47 follow)
  the same request, plain and exact: accepted
  when a proxy and a server disagree about where a request ends, the rest is read as the next customer's request
THREE. Header injection.
  the store puts the customer's search text in a redirect address
  a normal search, shoes: written
  search text with a line break and a second header: refused (a line break inside the value of Location)  <- WITHOUT THE CHECK THE ATTACKER SETS A COOKIE
  the answer is to refuse or encode line breaks in anything that reaches a header
FOUR. Cookies that carry a login.
  session=abc123
    problems: 3
    - no HttpOnly: a script in the page can read it
    - no Secure: it is also sent over plain HTTP
    - no SameSite: other sites can trigger requests that carry it
  session=abc123; Secure; HttpOnly; SameSite=Lax; Path=/
    problems: 0
  session=abc123; HttpOnly; SameSite=None
    problems: 2
    - no Secure: it is also sent over plain HTTP
    - SameSite=None without Secure: browsers reject it
  __Host-session=abc123; Secure; HttpOnly; SameSite=Strict; Path=/; Domain=shop.example
    problems: 1
    - the __Host- prefix needs Secure, Path=/ and no Domain
FIVE. Security headers on a real response.
  a real request to a plain server: status 200, body 'order A-1001 received'
  security headers present: 0 of 5
  the same request to a server that sets the five headers: 5 of 5
    Strict-Transport-Security: ok (max-age at least a year)
    Content-Security-Policy: ok (restricts where scripts load from)
    X-Content-Type-Options: ok (nosniff)
    X-Frame-Options: ok (DENY)
    Referrer-Policy: ok (strict-origin-when-cross-origin)
  headers present but set badly score 1 of 5: a header is only worth its value
