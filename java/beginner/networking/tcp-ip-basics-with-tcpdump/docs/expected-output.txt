  BEFORE RECORDING (the packets of one purchase):
    packet 1  [S]   40 bytes = IP 20 + TCP 20 + data 0
    packet 2  [S.]  40 bytes = IP 20 + TCP 20 + data 0
    packet 3  [.]   40 bytes = IP 20 + TCP 20 + data 0
    packet 4  [P.]  74 bytes = IP 20 + TCP 20 + data 34
    packet 5  [.]   40 bytes = IP 20 + TCP 20 + data 0
    5 packets, 234 bytes
  AFTER RECORDING (the pcap file):
    file header     24 bytes
    record headers  5 x 16 = 80 bytes
    packet bytes    234 bytes
    capture.pcap    24 + 80 + 234 = 338 bytes
  tcpdump, Wireshark and the Python script all read this file
TWO. Reading it back, in the style of tcpdump.
  WHAT TCPDUMP PRINTS (one packet, two lines):
    IP 198.51.100.7.51000 > 203.0.113.10.443:
       Flags [S], seq 1000, win 65535, length 0
    IP 203.0.113.10.443 > 198.51.100.7.51000:
       Flags [S.], seq 7000, ack 1001, win 65535, length 0
    IP 198.51.100.7.51000 > 203.0.113.10.443:
       Flags [.], ack 7001, win 65535, length 0
    IP 198.51.100.7.51000 > 203.0.113.10.443:
       Flags [P.], seq 1001:1035, ack 7001, win 65535, length 34
    IP 203.0.113.10.443 > 198.51.100.7.51000:
       Flags [.], ack 1035, win 65535, length 0
  S is SYN, a dot is ACK, P is PSH
  HOW THE NUMBERS FOLLOW:
    packet 2  ack 1001 = seq 1000 + 1
    packet 3  ack 7001 = seq 7000 + 1
    packet 5  ack 1035 = seq 1001 + 34 bytes of data
  a SYN counts as one byte

FOUR. How a checksum is made, step by step.
  the packet: the SYN from 100.64.0.99, as it was sent
  STEP 1. SPLIT INTO 16-BIT WORDS (checksum field 0000):
    pseudo-header  6440 0063 cb00 710a 0006 0014
    TCP header     9ca3 01bb 0000 0007 0000 0000
                   5002 ffff 0000 0000
  STEP 2. ADD THEM UP:
    sum            38f2d
  STEP 3. FOLD THE CARRY BACK IN:
    8f2d + 3 = 8f30
  STEP 4. FLIP EVERY BIT:
    checksum       70cf
  the checksum the packet carries: 70cf, the same: true

SIX. What a capture reveals.
