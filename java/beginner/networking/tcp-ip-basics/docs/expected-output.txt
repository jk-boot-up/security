ONE. Layers: a packet inside a packet.
  THE PACKET SENT (the customer's browser opens a connection):
    TCP segment  20 bytes  ports 51000 -> 443, SYN, seq 1000
    IP header    20 bytes  198.51.100.7 -> 203.0.113.10, TTL 64
    IP packet    40 bytes  = IP header + TCP segment
    ip   4500 0028 0000 0000 4006 148b c633 6407 cb00 710a
    tcp  c738 01bb 0000 03e8 0000 0000 5002 ffff 7cc1 0000
  THE PACKET RECEIVED (the shop decodes the 40 bytes):
    from  198.51.100.7 port 51000
    to    203.0.113.10 port 443
    SYN flag true, sequence number 1000
  the source address is just a field  <- ANYONE CAN WRITE IT
TWO. A checksum catches accidents, not attackers.
  HOW THE CHECKSUM IS MADE (IP header, checksum field 0000):
    words  4500 0028 0000 0000 4006 0000 c633 6407 cb00 710a
    sum    2eb72 (hex)
    fold   eb72 + 2 = eb74
    flip   ffff - eb74 = 148b  <- the checksum
  BEFORE THE CHANGE (as the customer sent it):
    time to live 64, checksum 148b: accepted
  AFTER THE CHANGE (time to live 64 -> 1 on the way):
    by accident, checksum kept 148b: refused
    by an attacker, new checksum 538b: accepted  <- NOT CAUGHT
  the checksum has no key, so anyone can make it match
THREE. The three-way handshake.
  THE REQUEST (customer -> shop):
    1. SYN      seq 1000
  THE RESPONSE (shop -> customer):
    2. SYN-ACK  seq 3120261316, ack 1001 (= 1000 + 1)
       half-open entries in the shop's table: 1
  THE REQUEST (customer -> shop):
    3. ACK      seq 1001, ack 3120261317 (= 3120261316 + 1)
  THE RESULT:
    established: true, half-open entries left: 0
    an ACK with no SYN before it: established: false
FOUR. A SYN flood.
  BEFORE THE FIX (a table of 8 half-open entries):
    8 SYNs from 100.64.0.1 to 100.64.0.8, never answered
    half-open entries: 8 of 8, the table is full
    a real customer's SYN answered: false  <- DENIAL OF SERVICE
  AFTER THE FIX (SYN cookies):
    the same 8 SYNs: half-open entries 0
    cookie = HMAC(secret, 198.51.100.7, 51000, 1000)
           = 1053972776, sent as the SYN-ACK's seq
    the ACK brings 1053972777 = cookie + 1: connects true
  the cost: few TCP options, and a hash for every SYN
FIVE. Guessable numbers, and a stream anyone can read.
  BEFORE THE FIX (a counter that adds 64000):
    the attacker's own SYN-ACK seq:     1000
    its guess for the admin (+ 64000):  65000
    what the shop really sent 10.0.0.5: 65000
    forged ACK accepted: true  <- A FORGED CONNECTION
  AFTER THE FIX (a keyed hash, RFC 6528):
    the attacker's own SYN-ACK seq:     692804923
    its guess for the admin (+ 64000):  692868923
    what the shop really sent 10.0.0.5: 1773183168
    forged ACK accepted: false
  THE STREAM SENT (a real connection on this machine):
    card=4111111111111111&order=A-1001
    connected true, the shop received every byte: true
  WHAT A SNIFFER ON THE WIRE SEES:
    card=4111111111111111&order=A-1001
    contains the card number: true  <- TCP HIDES NOTHING
  secrecy and identity come from TLS
