ONE. Layers: a packet inside a packet.
  a customer's browser sends a SYN from 198.51.100.7 to the shop 203.0.113.10 port 443
  the TCP segment is 20 bytes, and inside an IP packet it is 40 bytes
  decoded again: from 198.51.100.7 to 203.0.113.10, ports 51000 to 443, SYN flag: true
  nothing in either header says who the sender really is: the source address is just a field
TWO. A checksum catches accidents, not attackers.
  one byte changed in transit (the time to live): refused (IPv4 header checksum does not match)
  the same change made by someone who recomputes the checksum: accepted
  the checksum has no key, so anyone can make it match: it is not protection against an attacker
THREE. The three-way handshake.
  the customer sends SYN with sequence number 1000
  the shop answers SYN-ACK, acknowledging 1001, and now holds a half-open entry: 1
  the customer answers ACK: connection established: true, half-open entries left: 0
  an ACK with no SYN before it: established: false
FOUR. A SYN flood.
  8 SYNs from addresses that never answer fill the shop's table of 8 half-open entries: 8
  a real customer's SYN is now answered: false  <- THE SHOP IS DENYING SERVICE TO ITS CUSTOMERS
  with SYN cookies the shop keeps no entry: half-open entries 0, and the real customer connects: true
  the cost: cookies carry no options and take work for every SYN, so they are a defence for when the table is full
FIVE. Guessable numbers, and a stream anyone can read.
  the shop picks its numbers with a counter that adds 64000: the attacker, who sends a SYN pretending to be the admin machine 10.0.0.5, guesses the next number from its own connection and is accepted as the admin: true  <- A FORGED CONNECTION
  the shop picks its numbers with a keyed hash: the attacker, who sends a SYN pretending to be the admin machine 10.0.0.5, guesses the next number from its own connection and is accepted as the admin: false
  a real TCP connection on this machine: connected true, the server received every byte: true
  what a sniffer on the wire sees contains the card number: true  <- TCP DOES NOT HIDE ANYTHING
  TCP gives reliable, ordered delivery. Secrecy and identity come from TLS, which is the transport-security module
