ONE. A DNS message, byte by byte.
  the question for shop.example.com is 34 bytes: 12 of header, then the name as labels, then type and class
  its first 12 bytes: abcd01000001000000000000
  the answer repeats the name as a two byte pointer, so it is 50 bytes and not 66
  decoded again: shop.example.com is 203.0.113.10 for 300 seconds
  nothing in the message says who made the answer: only the id and the question have to match
TWO. The cache and the time to live.
  at second 0 the answer 203.0.113.10 arrives with a time to live of 300 seconds
  at second 100 the resolver answers from its cache: true, questions sent upstream so far: 1
  at second 300 the entry has expired and the resolver asks again: true
  caching makes DNS fast, and it also means one false answer is repeated to every customer until it expires
THREE. A real exchange over UDP on this machine.
  the client sent one datagram of 34 bytes and got one of 50 bytes back
  the answer arrived: true, repeats the id: true, says 203.0.113.10
  the name can be read in the query as plain text: true  <- ANYONE ON THE PATH SEES WHICH SITES YOU ASK FOR
  there is no connection and no signature: a datagram is believed if it looks right
FOUR. Cache poisoning by guessing.
  the resolver uses ids that count up, all queries from port 53: after 1000 forged answers the cache says 192.0.2.66  <- THE ATTACKER'S ADDRESS
  the resolver uses ids and ports from a keyed hash: after 1000 forged answers the cache says nothing
  with a keyed id and port the attacker must match one of 4227858432 pairs, and 1000 guesses are about one in 4227858
FIVE. How long a false answer lives, and what stops it.
  a false answer with a time to live of 86400 seconds, and the resolver caps lifetimes at 86400: still believed after 2 hours true
  a false answer with a time to live of 86400 seconds, and the resolver caps lifetimes at 3600: still believed after 2 hours false
  DNSSEC signs the answers, so a forged one fails a check that needs no trust in the path (described here, not run)
  DNS over TLS or HTTPS hides the questions and protects the path to the resolver, but not the data upstream
  the browser's check that the site's certificate names shop.example.com is the last line of defence, which is the transport-security module
