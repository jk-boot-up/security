ONE. Roles and permissions, and deny by default.
  the online store has 15 things that can be done, such as orders:read and refunds:approve
  the admin role allows 15 of 15
  the support role allows 3 of 15
  the warehouse role allows 3 of 15
  the finance role allows 3 of 15
  support asks for refunds:approve: DENY_DEFAULT  <- NOTHING ALLOWS IT, SO IT IS DENIED
  an admin with an explicit deny on secrets asks for secrets:read: DENY_EXPLICIT  <- A DENY BEATS ANY ALLOW
TWO. Blast radius: what a stolen credential can reach.
  the nightly order export runs as an admin, because that was quick: a stolen token reaches 15 of 15  <- EVERYTHING
  the same job with only the exporter role: a stolen token reaches 2 of 15
  an admin account with an explicit deny on secrets reaches 13 of 15
  the job needs only orders:read and reports:read, so everything else it was given is risk without benefit
THREE. Separation of duties: two people for a refund.
  alice (support) creates refund R-1: DONE
  alice tries to approve it: NOT_ALLOWED  (support cannot approve)
  dave (admin) creates refund R-2 and tries to approve it himself: DONE, then SAME_PERSON  <- ADMIN POWER DOES NOT REMOVE THE RULE
  carol (finance) approves R-1: DONE, approved: true
  nobody could move money alone, so one stolen account is not enough
FOUR. Access that expires by itself.
  carol (finance) is granted payments:write for ticks 10 to 12, for a month-end fix
  at tick 9 she can write payments: false
  at tick 10 she can write payments: true
  at tick 12 she can write payments: true
  at tick 13 she can write payments: false
  at tick 13 the grant is gone, and nobody had to remember to remove it
FIVE. Privilege creep, and the operating system.
  on day 200, of 5 permissions held, 2 were not used in the last 90 days:
    bob orders:read, never used
    carol payments:read, last used on day 100
  an export file with permissions rw-r--r-- is readable by others: true
  with permissions rw------- it is readable by others: false, and its folder is rwx------
  the Java SecurityManager that once limited code inside one program has been removed from the JDK
  the limits that remain are outside the program: separate operating system users, containers and separate processes
