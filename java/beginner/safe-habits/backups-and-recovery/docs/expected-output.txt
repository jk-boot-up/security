FOUR. Ransomware, and the copy it cannot change.
  THE COPIES BEFORE THE ATTACK
    shop server        3 files  writable
    mounted backup     3 files  writable
    versioned store    3 files  only adds, at time 100
    read-only folder   3 files  r--------
  THE ATTACK
    at time 200 it encrypts every file it can write
  AFTER THE ATTACK
    shop server        3 encrypted, orders.csv lost
    mounted backup     3 encrypted  <- WENT WITH THE DATA
    versioned store    2 versions: time 100 and 200
    read-only folder   0 encrypted, 3 blocked
  WHAT CAN BE RESTORED
    versioned store, version before 200: all back true
    read-only folder, after the same user runs chmod u+w:
      3 encrypted  <- THE SHOP'S ACCOUNT COULD UNLOCK IT
FIVE. Recovery point, recovery time, and a sealed backup.
  THE TIMELINE
    02:00  the last nightly backup
    15:30  the order database fails
    15:50  someone notices
    95 minutes for the restore, 12 orders an hour
  THE RECOVERY POINT (RPO): THE WORK LOST
    15:30 - 02:00 = 13:30, 13.5 h x 12 = 162 orders lost
  THE RECOVERY TIME (RTO): UNTIL THE SHOP IS BACK
    15:50 + 95 min = 17:25, 17:25 - 15:30 = 01:55
  WITH AN HOURLY BACKUP, THE LAST AT 15:00
    RPO 15:30 - 15:00 = 00:30, 0.5 h x 12 = 6 orders lost
    RTO 01:55, the same: backups do not speed restores
  THE ARCHIVE TO SEAL
    3 files, with customer names such as Ana
    name nightly-day-30, a random 256-bit key
    AES-256-GCM, the name bound in as associated data
  THE SEALED ARCHIVE
    shows the name Ana     false
    the right key          opens, 3 files
    another key            refused
    named nightly-day-31   refused, the name is sealed in
    the key file           rw-------, kept apart
    <- A LOST KEY IS A LOST BACKUP: THE KEY NEEDS ITS OWN COPY
