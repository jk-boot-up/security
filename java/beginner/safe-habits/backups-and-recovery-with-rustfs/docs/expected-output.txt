ONE. Versioning: an overwrite does not destroy the old data.
  THE BUCKET
    shop-orders, versioning on
  THE WRITES TO orders.csv
    1  the shop's orders, 40 bytes
    2  ransomware's scrambled bytes, 25 bytes
  THE HISTORY
    versions kept              2
    a normal read is 2         true
    version 1 is original      true
  THE RESTORE: COPY VERSION 1 BACK AS VERSION 3
    a normal read is original  true
    versions kept              3
    2 kept as evidence         true
  A PLAIN DELETE
    delete markers added       1
    a normal read              refused (404 NoSuchKey)
    version 1 still there      true
    <- WHOEVER CAN DELETE VERSIONS CAN STILL ERASE ALL
TWO. Object Lock: nobody can delete a locked version.
  THE BUCKET
    shop-backups, object lock on
  THE LOCKS
    backup-full.tar  COMPLIANCE  until now + 1 day
    backup-soft.tar  GOVERNANCE  until now + 1 day
  THE ROOT ACCOUNT TRIES THE COMPLIANCE VERSION
    delete the version         refused (403 AccessDenied)
    delete, bypass governance  refused (403 AccessDenied)
    shorten the retention      refused (403 AccessDenied)
    plain delete, a marker     allowed
    the version still reads    true
  THE ROOT ACCOUNT TRIES THE GOVERNANCE VERSION
    delete the version         refused (403 AccessDenied)
    delete, bypass governance  allowed
    <- COMPLIANCE: NOBODY UNTIL THE DATE. CHOOSE WITH CARE
THREE. The backup job gets an identity that can only add objects.

FOUR. A checksum catches a damaged backup.
  THE CHECKSUMS (SHA-256 IN BASE64)
    the backup   Du5R0k8IE/PhcdlE4tmKtfFjDbpcvgZLRF3U08cDIys=
    other bytes  U4p0HGInM6/hR4Gek52CzAce376z60ntcBpVl1rCiLM=
  THE UPLOADS
    checked.tar  the backup, with its own checksum
    damaged.tar  the backup, with other bytes' checksum
  THE ANSWERS
    checked.tar                allowed
    damaged.tar                refused (400 BadDigest)
  WHAT IS STORED
    checked.tar, same hash     true
    damaged.tar, versions      0
    <- INTACT IS NOT USABLE: STILL RUN A RESTORE TEST
FIVE. Keeping history without keeping it for ever, and the cost.
  THE LIFECYCLE RULE ON shop-orders
    rules 1, id expire-old-versions, Enabled
    an old version is removed 30 days after it is replaced
  THE COST, WORKED OUT
    orders.csv of 2 MB, overwritten every hour
    old versions kept: 24 x 30 days = 720
    storage: 720 x 2 MB = 1440 MB for one 2 MB file
  THE LIMITS
    a COMPLIANCE date set wrong is paid for in storage
    the root account can change every policy:
      keep it out of daily use
    a lock stops the API, not someone deleting the disks:
      keep a copy somewhere else too
