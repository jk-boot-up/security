TWO. The wildcard trap: "read everything".
  THE ROLE AS WRITTEN (report-reader, held by reporter):
    rule 1  get, list on *
    "read everything": it sounds read-only and harmless
  WHAT IT REALLY ALLOWS:
    get secrets         true  <- EVERY PASSWORD AND KEY
    update deployments  false
    reaches 16 of 56: 2 verbs x 8 resources
  * also covers kinds added after the role was written;
  name the resources, and use resourceNames for one object
THREE. Ways to become more powerful than you were given.
  THE ROLE (deployer, held by ci-deployer):
    rule 1  get, list, create on pods
    rule 2  get, list, create, update, patch on deployments
    rule 3  create on rolebindings
    rule 4  bind, escalate on roles
  THE ESCALATION PATHS (exporter 0, ci-deployer 4):
    create pods, which can mount any secret or token
    create role bindings
    bind roles it does not hold
    edit roles to add permissions it does not hold
  ci-deployer: get secrets false, but create pods true
  a pod can mount the secrets  <- CREATE PODS = READ SECRETS
  and bind or escalate = owning the namespace
