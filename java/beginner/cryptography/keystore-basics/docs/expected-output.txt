ONE. A key written in the source code.
  the bank compiles a program with its key inside it
  the key's text is found inside the compiled class file: true  <- ANYONE WITH THE PROGRAM HAS THE KEY
  it is also in the source repository, every copy of the program and every build, for good
  changing the key means building and shipping the program again
TWO. A key in a file outside the program.
  the key is no longer in the program, and is in a file with permissions rw-r--r--
  readable by others on the machine: true  <- ANYONE WITH A LOGIN CAN READ IT
  with permissions rw-------, readable by others: false
  but the file holds the key in the clear, so anyone who can read it, or its backup, has the key
THREE. A PKCS12 keystore: an encrypted file of keys.
  the key is saved in bank.p12 under the name statements-v1
  the key's own bytes appear in the file: false
  the name of the key appears in the file: false
  opened with the password, the key comes back: true
  opened with a wrong password: refused
  the password makes the key that protects the file, and the file records the rounds: [10000]
  saved again with the setting raised to 600000, the file records: [10000, 600000]
  the raised setting reached one place and not another: check what the file records, not only the settings
FOUR. Making keys from other secrets.
  a key made from a password and a salt with PBKDF2, 600000 rounds: 32 bytes
  the same password and salt give the same key: true
  another salt gives another key: true
  from one master key, HKDF makes a separate key for each purpose: true
  asking again for the same purpose gives the same key: true
  a key made from a weak password is only as strong as the password
FIVE. Replacing a key, and the bill.
  a new key, statements-v2, is added; the old message names statements-v1 and the new one statements-v2
  both still open: ANA-1: balance 1200 and ANA-1: balance 1200
  after statements-v1 is removed, the old message: refused, its key is gone
  so old messages must be sealed again with the new key before the old key goes
  the keystore's password has to be kept somewhere too, and a lost keystore file is lost data
  the default rounds of the file are far below the 600000 now recommended, so raise them and choose a strong password
