ONE. One call, and no nonce to look after.
  the same line sealed twice gives the same bytes: false  <- TINK PICKS A NEW NONCE
  the stored message starts with 01000003e9: version 1, then key id 1001
  16 bytes seal to 49 bytes: 5 for the key id, 12 for the nonce, 16 for the tag
  opened with the right key and account: RENT      -1200
TWO. Any change is refused.
  one bit of the message is flipped: refused  <- DETECTED
  the message is moved to another account: refused  <- DETECTED
  opened with a different key of the same id: refused
THREE. Replacing the key without losing the data.
  a new key is added and made primary: the keyset now holds 2 keys
  a message sealed before the change still opens: RENT      -1200
  a new message starts with a different key id: true
  the old key is removed from the keyset: refused for old messages, RENT      -1200 for new ones
FOUR. Keeping the keyset itself safe.
  the keyset is written encrypted with a master key: the file has an encryptedKeyset field: true
  the key's own bytes appear in the file: false
  read back with the master key, it opens the old message: RENT      -1200
  read back with a different master key: refused
FIVE. The bill: what Tink decides for you, and what it does not.
  the AEAD templates offered include: AES128_GCM, AES256_GCM, AES128_EAX, AES256_CTR_HMAC_SHA256, CHACHA20_POLY1305, XCHACHA20_POLY1305, AES256_GCM_SIV
  an ECB template: not offered  <- THE UNSAFE CHOICE IS NOT ON THE MENU
  the stored format is Tink's own: other libraries need Tink to read it
  Tink adds a library and its protocol buffer dependency, and the master key still has to live somewhere
  and message lengths still show: 33 bytes more than the message, every time
