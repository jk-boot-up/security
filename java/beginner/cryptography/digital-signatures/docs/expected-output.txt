THREE. How the signature is made, step by step.
  STEP 1. HASH THE PRIVATE KEY (SHA-512), CUT IN TWO
    secret a     307c8386 4f2833cb 427a2ef1 c00a013c ...
    prefix       9b4f0afe 280b746a 778684e7 54425020 ...
    A = a x B    d75a9801 82b10ab7 d54bfed3 c964073a ...
  STEP 2. r = SHA-512(prefix + message) mod L
    r            407edecf b2e451e3 de457d5f d71dce50 ...
  STEP 3. R = r x B: the first 32 bytes of the signature
    R            a83b53e9 ba4d832c fa721a3f e058732d ...
  STEP 4. k = SHA-512(R + A + message) mod L
    k            21d7070c 464ff9d1 e299cbea bc5b58ae ...
  STEP 5. S = (r + k x a) mod L: the last 32 bytes
    S            193b6f5a b8906deb cc2f3a23 1634677d ...
    R + S is Java's own signature: true
  CHECKING (public key only): S x B = R + k x A
    the real list:  true
    mouse=24:       false
FOUR. What exactly is signed.

FIVE. A good signature on an old message.
  BEFORE (both genuinely signed by the shop):
    version 1    version=1 validUntilDay=100 laptop=1000 mouse=20
    version 2    version=2 validUntilDay=100 laptop=1200 mouse=25
  THE ATTACK (version 1 replayed on day 50):
    signature checked only: OK  <- PERFECT SIGNATURE, OLD LIST
  AFTER THE FIX (version and expiry are checked):
    a checkout that has seen version 2: OLD_VERSION
    valid until day 40, offered on day 50: EXPIRED
    both are inside the signed bytes, so nobody can change them
SIX. The bill: whose key is it, and what if it is stolen?
  THE ATTACK (Mallory's key, said to be the shop's):
    Mallory's list: OK  <- ONLY AS GOOD AS THE KEY
  AFTER THE FIX (the shop's real public key):
    Mallory's list: BAD_SIGNATURE
  WHAT A SIGNATURE CANNOT DO:
    stop a stolen private key: OK  <- UNTIL IT IS REVOKED
    hide anything: the price list is readable by anyone
    bytes: signature 64, public key 32, encoded key 44
