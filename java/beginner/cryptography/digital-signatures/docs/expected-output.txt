ONE. A tag made with a shared key.
  the shop tags its price list with HMAC: 2efbd273904d2215
  the warehouse must be able to check the tag, so it holds the same key
  the warehouse tags a list of its own, with the laptop at 12 dollars: accepted  <- ANYONE WHO CAN CHECK CAN FORGE
TWO. A signature: made with the private key, checked with the public key.
  the shop signs its price list: 64 bytes, beginning a83b53e9ba4d832c
  signing it again gives the same bytes: true  <- NO RANDOM NUMBER IS NEEDED
  the warehouse holds only the public key and checks it: OK
  the laptop is changed to 12 dollars, the signature kept: BAD_SIGNATURE
  Mallory signs her own list with her own key: BAD_SIGNATURE
  the warehouse can check but cannot make one: no key it holds can sign for the shop
THREE. What exactly is signed.
  two lists with the same products, built in a different order, give the same bytes: true
  the shop signs the same bytes for another purpose, a refund order, with the label shop.refund.v1
  that signature, checked as a refund order: true
  that signature, offered as a price list: refused  <- A SIGNATURE IS TIED TO ITS PURPOSE
  the message and the label are separated by a zero byte, so one cannot run into the other
FOUR. A good signature on an old message.
  the shop published version 1 (a laptop at 1000), then version 2 (at 1200)
  an attacker replays the old, genuinely signed, version 1 on day 50: OK  <- THE SIGNATURE IS PERFECT, THE LIST IS OLD
  a checkout that remembers the newest version: OLD_VERSION
  a list that was only good until day 40, offered on day 50: EXPIRED
  the version and the expiry are inside what is signed, so nobody can change them
FIVE. The bill: whose key is it, and what if it is stolen?
  Mallory gives the checkout her public key and says it is the shop's: OK  <- THE CHECK IS ONLY AS GOOD AS THE KEY
  with the shop's real key in the checkout: BAD_SIGNATURE
  if the shop's private key is stolen, the thief's list is accepted: OK  <- UNTIL THE KEY IS REVOKED
  a signature hides nothing: the price list is readable by anyone, signed or not
  sizes: a signature is 64 bytes, a raw public key 32, and the same key encoded 44
