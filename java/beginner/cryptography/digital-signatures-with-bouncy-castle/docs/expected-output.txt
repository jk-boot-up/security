ONE. A standard signed message: CMS SignedData.
  the bank signs a statement with its ECDSA key and puts its certificate in the message
  attached (the statement travels inside) verifies with the certificate: true
  detached (the statement travels separately) verifies when the statement is supplied: true
  the detached signature with a changed statement: refused
  the attached message with one bit changed inside it: refused
  checked against somebody else's certificate: refused
  the signing time inside is 2026-03-01T09:30:00Z: covered by the signature, but it is the signer's word
TWO. ECDSA: the nonce that must never repeat.
  deterministic signing (RFC 6979) of the same message twice gives the same signature: true
  and it matches the value published in RFC 6979 appendix A.2.5: true
  randomized signing of the same message twice gives different signatures: true, and both verify: true
  two signatures made with the same nonce let anyone compute the private key: true  <- NEVER REUSE A NONCE
  deterministic signing removes the risk, and so does Ed25519, which is the next demo
THREE. EdDSA: Ed25519 and Ed448.
  an Ed25519 signature is 64 bytes and matches RFC 8032: true
  an Ed448 signature is 114 bytes and matches RFC 8032: true
  signing again gives the same bytes, with no random number involved: true and true
  both verify: true; one flipped bit in an Ed25519 signature: refused
FOUR. A compact signed token: JWS.
  signing the RFC 8037 example gives exactly the token in the RFC: true
  it verifies: true
  detached form has an empty middle part (true) and verifies when the payload is supplied: true
  a token that claims alg none and has no signature: refused
  the same signature with a different payload: refused
  the verifier decides the algorithm, not the token: that is what stops alg none and key confusion
FIVE. Text armor, and the bill.
  a signed message as PEM text begins with -----BEGIN CMS-----: true
  and reads back to the same bytes: true
  a valid signature proves that the key signed, not who owns the key: that needs a chain of certificates
  the signing time is the signer's claim: a trusted time needs a timestamp authority (RFC 3161), described here and not run
  the private key still needs a home: see keystore-basics
  openssl checks these same files in the integration tests: cms -verify, pkeyutl -verify and dgst -verify
