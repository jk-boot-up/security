ONE. A standard signed message: CMS SignedData.
  BEFORE SIGNING (what the bank has):
    statement    Statement ANA-1: balance 1200
    SHA-256      6e158e90 b7240b23 b2ab7b15 df674425
                 e32dcadc 3ebad737 c051d8d5 324fb981
    time         2026-03-01T09:30:00Z
  AFTER SIGNING (inside the CMS message):
    signer       CN=Statements,O=Example Bank
    digest       6e158e90 b7240b23 b2ab7b15 df674425
                 e32dcadc 3ebad737 c051d8d5 324fb981
    same as the statement's SHA-256: true
    signature    ECDSA over the digest and the time
  THE CHECKS (with the bank's certificate):
    attached, statement inside: verifies
    detached, statement supplied: verifies
    detached, balance changed to 9200: refused
    attached, one bit changed inside: refused
    somebody else's certificate: refused
  signed time 2026-03-01T09:30:00Z: the signer's word
TWO. How an ECDSA signature is made, step by step.
  BEFORE SIGNING (the inputs):
    message      Statement ANA-1: balance 1200
    private key  c9afa9d8 45ba7516 6b5c2157 67b1d693
                 4e50c3db 36e89b12 7b8a622b 120f6721
  STEP 1. HASH THE MESSAGE: h = SHA-256(message)
    h            6e158e90 b7240b23 b2ab7b15 df674425
                 e32dcadc 3ebad737 c051d8d5 324fb981
  STEP 2. A ONE-TIME NUMBER k, FROM KEY AND h (RFC 6979)
    k            8a55aacb f10510b9 2b5cc886 30a85458
                 ebd42241 d0c31211 850993bd ff6f1904
  STEP 3. r = THE x OF THE CURVE POINT k TIMES G
    r            bc88ec8d ee35125f 43900323 513c844b
                 a223044d de5c6f4f fca225ff c4f1e365
  STEP 4. s = (h + r TIMES KEY) / k, MODULO n
    s            ef0d3fda f8310087 798da89f 09f7830e
                 061ce37a 30bd9494 343a530f 92211745
  AFTER SIGNING: the signature is r and s, 64 bytes
  THE CHECK, WITH THE PUBLIC KEY Q: x of (h/s) G + (r/s) Q
    x            bc88ec8d ee35125f 43900323 513c844b
                 a223044d de5c6f4f fca225ff c4f1e365
    x = r: verifies; balance 9200: refused
    same as Bouncy Castle: true; RFC 6979 "sample": true
THREE. The nonce that must never repeat.
  THE MISTAKE: one k for two payments
    message 1    pay 10 to Bob
    message 2    pay 99 to Eve
    the same r in both signatures: true  <- THE REUSE SHOWS
  THE ATTACK, WITHOUT THE KEY:
    k = (h1 - h2) / (s1 - s2)
    k            12345678 90abcdef 12345678 90abcdef
                 12345678 90abcdef 12345678 90abcdef
    key = (s1 times k - h1) / r
    key          c9afa9d8 45ba7516 6b5c2157 67b1d693
                 4e50c3db 36e89b12 7b8a622b 120f6721
    the bank's private key: true  <- NEVER REUSE A NONCE
  THE FIX, ONE: a deterministic k (RFC 6979)
    the statement signed twice, same r and s: true
    random k: they differ: true, both verify: true
  THE FIX, TWO: Ed25519 and Ed448 need no random number
    Ed25519: 64 bytes, matches RFC 8032: true
    Ed448: 114 bytes, matches RFC 8032: true
    signed again, the same bytes: true and true
    both verify: true; one flipped bit: refused
FOUR. A compact signed token: JWS.
  BEFORE SIGNING (the RFC 8037 example):
    header       {"alg":"EdDSA"}
    payload      Example of Ed25519 signing
  AFTER SIGNING (each part base64url, joined by dots):
    header       eyJhbGciOiJFZERTQSJ9
    payload      RXhhbXBsZSBvZiBFZDI1NTE5IHNpZ25pbmc
    signature    hgyY0il_MGCjP0JzlnLWG1PPOt7-09PGcvMg3AIbQR6
                 dWbhijcNR4ki4iylGjg5BhVsPt9g7sVvpAr_MuM0KAg
    the token in RFC 8037: true; it verifies: true
  THE CHECKS (the verifier expects EdDSA, always):
    detached (empty middle), payload given: verifies
    header says alg none, no signature: refused
    the same signature, another payload: refused
  the verifier decides the algorithm, not the token
FIVE. Text armor, and the bill.
  BEFORE ARMOR: the signed CMS message, as binary bytes
  AFTER ARMOR (PEM: Base64 text between two lines):
    first line   -----BEGIN CMS-----
    last line    -----END CMS-----
    no line over 64 characters: true
    reads back to the same bytes: true
  THE BILL (what a valid signature does not tell you):
    who owns the key: that needs a chain of certificates
    when it was signed: that needs a timestamp authority
    where the private key lives: see keystore-basics
  openssl checks these files in the integration tests
