ONE. The problem: sharing a key.
  the bank wants to send Ana an encrypted statement, and sends the key over the open network first
  Eve sees every message on the wire, including the key: true  <- EVE CAN OPEN ANYTHING NOW
  a secret key cannot be sent in the clear, and the bank and Ana have never met
TWO. A key pair: lock with the public key, open with the private key.
  Ana publishes her public key, 294 bytes, and keeps the private key
  the bank locks the 32-byte key with it: 256 bytes on the wire
  Ana opens it: true
  Eve has the public key and the locked message, and tries her own private key: refused
  locking the same key again gives the same bytes: false  <- OAEP ADDS RANDOMNESS
  at most 190 bytes fit: one byte more is refused
THREE. Hybrid encryption: RSA for the key, AES for the data.
  a 10000-byte statement is sealed with a fresh AES key, and only that key is locked with RSA
  the envelope: 256 bytes of locked key, 12 of nonce, 10016 of cipher text and tag: 10284 in all
  Ana opens it: true
  Eve tries her own private key: refused
  one bit of the cipher text is flipped: refused
FOUR. Key agreement: no key is sent at all.
  the bank and Ana swap public keys, 44 bytes each, and nothing else
  each combines its own private key with the other's public key and gets a 32-byte key
  the two keys are the same: true
  Eve saw both public keys and makes her own: her key is the same too: false
  a new session with a new bank key gives a different key: true  <- AN OLD SESSION'S KEY IS NOT IN THE NEW ONE
FIVE. The bill: whose key is it?
  Mallory swaps Ana's public key for her own, and the bank locks a message to the wrong key
  Mallory reads it: PIN is 4821, locks it again for Ana, and sends it on
  Ana opens what she receives: PIN is 4821  <- NOBODY NOTICED
  nothing in the maths says whose public key it is: signatures and certificates are the answer
  sizes: an RSA-2048 public key is 294 bytes, an X25519 one is 44
  and a stolen private key opens every message ever locked to its public key
