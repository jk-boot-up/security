ONE. The problem: sharing a key.
  WHAT THE BANK SENDS (the key, in the clear):
    key   statement-key-32-bytes-long-demo
  WHAT EVE SEES ON THE WIRE:
    key   statement-key-32-bytes-long-demo
  Eve's copy is the key: true  <- EVE HAS IT
  they have never met: no safe way to hand it over
TWO. A key pair: the public key locks, the private key opens.
  BY HAND, WITH TINY NUMBERS:
    two primes     p = 89, q = 97
    public key     n = p x q = 8633, e = 17
    private key    d = 497, as 17 x 497 = 8449 = 88 x 96 + 1
  BEFORE ENCRYPTION:
    message        m = 4821
  AFTER ENCRYPTION (with the public key):
    locked         c = m^e mod n = 4485
  OPENING (with the private key):
    opened         c^d mod n = 4821
    locked again   4485, the same  <- NO RANDOMNESS
  REAL RSA-2048 WITH OAEP PADDING:
    Ana's public key   294 bytes, published
  BEFORE ENCRYPTION:
    the key            32 bytes
  AFTER ENCRYPTION:
    on the wire        256 bytes
  OPENING:
    Ana's private key  opens it: true
    Eve's private key  refused
    locked again, the same bytes: false  <- OAEP ADDS RANDOMNESS
  at most 190 bytes fit: one byte more is refused
THREE. Hybrid encryption: RSA for the key, AES for the data.
  BEFORE ENCRYPTION:
    statement      10000 bytes, far too big for RSA
    fresh AES key  32 bytes, made for this one message
  AFTER ENCRYPTION (the envelope):
    locked key     256 bytes (the AES key, locked with RSA)
    nonce          12 bytes
    cipher text    10016 bytes (10000 + a 16-byte tag)
    in all         10284 bytes
  OPENING:
    Ana's private key: true
    Eve's private key: refused
    one bit of the cipher text flipped: refused
FOUR. Key agreement: no key is sent at all.
  BY HAND, WITH TINY NUMBERS (everyone knows g = 5, p = 23):
    bank secret 6    sends 5^6 mod 23 = 8
    Ana secret 15    sends 5^15 mod 23 = 19
    bank gets        19^6 mod 23 = 2
    Ana gets         8^15 mod 23 = 2  <- THE SAME, NEVER SENT
  BEFORE THE SWAP (real X25519 keys, from RFC 7748):
    bank private  77076d0a 7318a57d 3c16c172 51b26645 ...
    bank public   8520f009 8930a754 748b7ddc b43ef75a ...
    Ana private   5dab087e 624a8a4b 79e17f8b 83800ee6 ...
    Ana public    de9edb7d 7b7dc1b4 d35b61c2 ece43537 ...
  AFTER THE SWAP (own private + other's public key):
    bank gets     4a5d9d5b a4ce2de1 728e3bf4 80350f25 ...
    Ana gets      4a5d9d5b a4ce2de1 728e3bf4 80350f25 ...
    the same secret: true
  HKDF turns the secret into a 32-byte key:
    key           34501e3e d961431b 28ea6246 60fef575 ...
  on the wire: two public keys, 44 bytes each, nothing else
  Eve, with a key pair of her own: the same key: false
  a new session, a new bank key: a different key: true
FIVE. The bill: whose key is it?
  WHAT THE BANK SENDS:
    message       PIN is 4821
    locked to     Mallory's public key, swapped in for Ana's
  IN THE MIDDLE, MALLORY:
    reads         PIN is 4821
    locks it again with Ana's real public key, sends it on
  WHAT ANA RECEIVES:
    opened        PIN is 4821  <- NOBODY NOTICED
  nothing in the maths says whose public key it is
  public keys: RSA-2048 294 bytes, X25519 44 bytes
  a stolen private key opens every message locked to it
