ONE. Base64 is an encoding, not encryption.
  THE SECRET (kubectl create secret generic):
    name   payments/card-key
    key    demo-card-vault-key-001
  WHAT THE API RETURNS (data.key):
    ZGVtby1jYXJkLXZhdWx0LWtleS0wMDE=
  HOW BASE64 IS UNDONE (first 4 characters, no key):
    characters  Z, G, V, t
    place in    25 6 21 45 (A=0 ... Z=25, a=26 ... z=51)
    6 bits      011001 000110 010101 101101
    8 bits      01100100 01100101 01101101
    bytes       100 101 109 = "dem"
    all of it   demo-card-vault-key-001
  WHO CAN READ IT:
    auditor (may only list secrets)  reads the value: yes
    nobody (no rule on secrets)      reads the value: no
TWO. Raw etcd, before encryption.
  THE READ (etcdctl, inside the etcd pod):
    get /registry/secrets/payments/card-key
  WHAT ETCD HOLDS:
    starts with      k8s.....v1..Secret..  (. = not a letter)
    the card key     as plain text: yes
    its base64 form  no
  THE 7 BYTES IN FRONT OF THE CARD KEY (hex):
    0a 03     field 1, length 3
    6b 65 79  "key", the name in data
    12 17     field 2, length 0x17 = 23
    then      demo-card-vault-key-001 (23 characters)
  EVERY SECRET IN ETCD:
    encrypted   0 of 2
THREE. Encryption at rest.
  THE ENCRYPTION CONFIGURATION (the API server restarted):
    resources   secrets
    provider 1  aescbc, key1: 32 random bytes, not printed
    provider 2  identity: reads what was stored plain
  BEFORE THE REWRITE:
    card-key (written before)  plain text: yes
    card-key-2 (written after)  encrypted: yes, plain text: no
    kubectl returns card-key-2 as before: yes
    secrets encrypted  1 of 3
  WHAT ETCD HOLDS FOR card-key-2:
    starts with  k8s:enc:aescbc:v1:key1:
    k8s:enc   encrypted by the API server
    aescbc    the provider: AES in CBC mode
    v1        the provider's format version
    key1      the key's name in the configuration
    then      bytes that look random; "Secret" in them: no
  AFTER THE REWRITE (kubectl replace of every secret):
    card-key  encrypted: yes, plain text: no
    secrets encrypted  3 of 3
    the card key anywhere in etcd: no
  WHAT IT DOES NOT CHANGE:
    the key is a file on the control-plane node: yes
    the auditor still reads the value: yes
FOUR. OpenBao and a 10 second token.
  THE ROLE IN OPENBAO (auth/kubernetes/role/payments):
    who       ServiceAccount payments/payments-app
    audience  openbao
    policy    payments-read: read secret/data/payments/db
    token     10 seconds
  WHERE THE DATABASE PASSWORD IS:
    in OpenBao: yes, in a Kubernetes Secret: no, in etcd: no
  THE LOGIN (payments-app sends its pod's token):
    sub       system:serviceaccount:payments:payments-app
    aud       openbao
  THE RESPONSE:
    HTTP 200, a token for 10 seconds
    policies  default, payments-read
  READING THE PASSWORD WITH THAT TOKEN:
    at once     HTTP 200, the right value: yes
    12 s later  12 > 10, expired: HTTP 403
  ANOTHER POD LOGS IN (other-app):
    sub       system:serviceaccount:payments:other-app
    HTTP 403: not the role's ServiceAccount
FIVE. A bound ServiceAccount token.
  THE BOUND TOKEN (kubectl create token, 10 minutes):
    claims    aud exp iat iss jti kubernetes.io nbf sub
    lifetime  exp - iat = 600 seconds
    audience  openbao
    pod       report-job
  THE OLD TOKEN (a Secret of type service-account-token):
    claims    6, among them exp: no, aud: no
    lifetime  no exp: it never expires
    pod       none
  THE API SERVER'S ANSWER (a TokenReview of each):
    while report-job runs  bound: yes, old: yes
    after it is deleted    bound: no, old: yes
