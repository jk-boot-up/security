ONE. One flat network.
  six containers (web, app, db, cache, admin, ci) on one Docker network, each listening on its port
  the front is taken over; what it reaches by name: [app, db, cache, admin, ci]  <- THE DATABASE, THE CACHE, THE ADMIN PANEL AND THE BUILD SERVER
  pairs that can talk, in either direction: 15 of 15; the design wanted 6
TWO. Three networks: front, back, management.
  web and app on front; app, db, cache and admin on back (no route out); admin and ci on mgmt
  the front is taken over: [app], and by address, after scanning every address it can learn: [app]
  pairs that can talk: 8 of 15; the design wanted 6; extra: 2 [admin-cache, cache-db], missing: 0
  everything on a network can talk to everything else on it, so the coarse layout lets the cache talk to the database and the admin panel to the cache, which nobody asked for
THREE. The design as code, and a layout built from it.
  the intent: 6 pairs [admin-app, admin-ci, admin-db, app-cache, app-db, app-web]
  one internal network for each pair, and each service on the networks of its pairs: measured 6 pairs, extra 0, missing 0
  the front is taken over: by name [app], by address [app]
  someone with the Docker socket joins web and db to one more network: extra [db-web]  <- DRIFT, FOUND BY MEASURING AGAINST THE INTENT
FOUR. The edge: what is published, and what can leave.
  published to the host: web yes, app no, db no, and the host can open web's port: true
  an attacker's server on the internet side; the services that can reach it: [web]  <- INTERNAL NETWORKS HAVE NO WAY OUT, THE FRONT HAS ONE
  a taken-over database cannot send anything out, and a taken-over front still can: its way out is the next thing to close
FIVE. The bill.
  names are scoped to networks: a service that is on two networks (app is on four) is a pivot, and the pivots are where an attacker goes next
  reachable is not authorised: the database port is open to the application, and whether the application may use it is for the database to decide
  whoever can use the Docker socket can join any container to any network, so the socket is worth more than every rule above
  one network for each pair does not scale to a hundred services, which is why clouds have security groups and clusters have network policies, and why those need testing as this does
  measure against the intent, in the build and on a schedule: a diagram of the network is a wish, and the measurement is the network
