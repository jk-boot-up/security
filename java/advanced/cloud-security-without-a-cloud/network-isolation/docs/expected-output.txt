ONE. One flat network.
  THE SERVICES (one container each, listening on a port):
    web    8000  the public front
    app    8080  the application
    db     5432  the accounts database
    cache  6379  the session cache
    admin  9000  the admin panel
    ci     2222  the build server
  THE LAYOUT:
    flat   web app db cache admin ci  has a way out
  THE ATTACK: web, the public front, is taken over
  WHAT web REACHES BY NAME (measured with nc):
    app db cache admin ci  <- EVERYTHING
  HOW MANY PAIRS CAN TALK (n services make n x (n-1) / 2):
    flat   6 services  6 x 5 / 2 = 15
    measured 15 of 15 possible pairs
  AGAINST THE DESIGN (6 pairs wanted):
    extra    9  admin-cache admin-web app-ci cache-ci
             cache-db cache-web ci-db ci-web
             db-web
    missing  0
TWO. Three networks: front, back, management.
  THE LAYOUT:
    front  web app                    has a way out
    back   app db cache admin         internal
    mgmt   admin ci                   internal
  WHAT web REACHES (measured):
    by name     app
    by address  app   (every address it can learn)
  HOW MANY PAIRS CAN TALK:
    front  2 services  2 x 1 / 2 = 1
    back   4 services  4 x 3 / 2 = 6
    mgmt   2 services  2 x 1 / 2 = 1
    together 8, as distinct pairs 8
    measured 8 of 15 possible pairs
  AGAINST THE DESIGN (6 pairs wanted):
    extra    2  admin-cache cache-db
    missing  0
  WHY: everything on back talks to everything else on back
THREE. The design as code, and a layout built from it.
  THE INTENT (the pairs that may talk):
    admin-app admin-ci admin-db
    app-cache app-db app-web
  THE LAYOUT BUILT FROM IT (one network per pair):
    link1  admin app                  internal
    link2  admin ci                   internal
    link3  admin db                   internal
    link4  app cache                  internal
    link5  app db                     internal
    link6  app web                    internal
    edge   web                        has a way out
  THE MEASUREMENT:
    pairs 6, extra 0, missing 0
    web reaches by name app, by address app
  THE DRIFT: someone with the Docker socket runs
    docker network create --internal oops
    docker network connect oops web, and the same for db
  THE MEASUREMENT AFTER THE DRIFT:
    pairs 7, extra db-web  <- FOUND BY MEASURING
FOUR. The edge: what is published, and what can leave.
  THE WAY IN: ports published to the host (127.0.0.1)
    web    published, the host connects: yes
    app    not published
    db     not published
    cache  not published
    admin  not published
    ci     not published
  THE WAY OUT: an attacker's server, evil:4444, on edge
  WHO REACHES IT (measured):
    web    yes  <- THE FRONT HAS A WAY OUT
    app    no
    db     no
    cache  no
    admin  no
    ci     no
  HOW IT IS WORKED OUT:
    only edge has a way out, and only web is on edge
    worked out web, measured web
FIVE. The bill.
  THE PIVOTS (services on two or more networks):
    web    2 networks  link6 edge
    app    4 networks  link1 link4 link5 link6
    db     2 networks  link3 link5
    admin  3 networks  link1 link2 link3
    a taken-over pivot reaches every network it is on
  WHAT THE NETWORK DOES NOT DECIDE:
    reachable is not authorised: db still checks who app is
    the Docker socket can join anything to any network
  WHAT IT COSTS:
    one network per pair: 7 networks for 6 services
    at scale: security groups and network policies, tested
    the same way, against the intent, on a schedule
