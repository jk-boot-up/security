FIVE. The guard: a canary file and entropy.
  HOW ENTROPY IS WORKED OUT (one block of 4096 bytes):
    H = sum over the byte values of -p x log2(p), p = count / 4096
  THE LEDGER TEXT, BEFORE ENCRYPTION:
    '1'    count  633  p 0.1545  -p x log2(p) 0.4163
    ','    count  480  p 0.1172  -p x log2(p) 0.3625
    '0'    count  419  p 0.1023  -p x log2(p) 0.3365
    ... 18 byte values in all, H = 3.93 bits per byte
  THE SAME BLOCK, AFTER AES ENCRYPTION:
    'v'    count   28  p 0.0068  -p x log2(p) 0.0492
    0xea   count   28  p 0.0068  -p x log2(p) 0.0492
    0x20   count   27  p 0.0066  -p x log2(p) 0.0478
    ... 256 byte values in all, H = 7.95 bits per byte
  THE DETECTORS (each one alone stops the backup):
    canary  the SHA-256 of zz-canary-accounts.csv changed
    file    the entropy of a whole file is above 7.5
    block   the entropy of any 4 KiB block is above 7.5
  THE DIRECTORIES TESTED (9 files: 8 days + the canary):
                                 enc  canary file block backup
    healthy                        0  no     no   no    allowed
    AES, every file                9  yes    yes  yes   refused
    AES, canary skipped            8  no     yes  yes   refused
    AES on half, canary skipped    8  no     no   yes   refused
    healthy + compressed export    0  no     yes  yes   refused
    a false alarm: compressed data looks like ciphertext
